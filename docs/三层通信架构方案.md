# 智能三角警示牌 — 三层通信架构方案

> **状态**：草案 / 待定（协议细节尚未确定）
> **日期**：2026-10-12
> **适用项目**：三角警示牌作业人员 APP（`com.example.myapplication`）
> **前置文档**：《智能三角警示牌作业人员 APP 需求规格说明书》

---

## 0. 背景与变更

原方案是 **手机 ↔ 小车 直连**（手机连小车热点 `192.168.4.1`，HTTP 直连 ESP32）。

现改为 **三层中转**：手机 ↔ 服务端 ↔ 小车。三者同处一个局域网，各自有独立 IP。

**变更动机**：
- 手机不再是小车热点的客户端，**可以正常上网** → 高德地图直接出图（原方案"连热点就没网"的硬伤消失）
- 天然支持多车（服务端按设备路由）
- 小车可离线缓存、断线重传，由服务端负责
- 安全性更好：手机不直连小车，服务端可做鉴权/限流

---

## 1. 目标架构

```
┌──────────┐   ①指令    ┌──────────┐   ③指令    ┌──────────┐
│ 手机 APP │ ─────────→ │ 服务端   │ ─────────→ │ 小车     │
│(Android) │            │(局域网)  │            │ (ESP32)  │
│          │ ←───────── │          │ ←───────── │          │
└──────────┘   ④状态    └──────────┘   ②状态    └──────────┘
      ↑                        ↕
      └──── 界面渲染 ←─────────┘
```

**数据流**：

| 序号 | 方向 | 内容 | 频率 |
|---|---|---|---|
| ① | 手机 → 服务端 | 控制指令（遥控/布置/急停/回收/灯光） | 事件触发；遥控保持包 300ms |
| ② | 小车 → 服务端 | 设备状态（模式/运动/电量/进度/传感器/位置） | 1Hz 或事件 |
| ③ | 服务端 → 小车 | 转发的控制指令 | 同 ① |
| ④ | 服务端 → 手机 | 聚合后的状态数据 | 轮询 1Hz 或 WebSocket 推送 |

**拓扑约束**：三者同一局域网，各自独立 IP（手机 DHCP、服务端静态、小车静态或 DHCP）。

## 2. 「外部通信」边界定义

> 判据：**这段代码会不会把数据发到手机以外，或从手机以外收数据**。会 → 外部。

### ✅ 算外部（收进 `external/ExternalApi.kt`）

| 项 | 说明 |
|---|---|
| **服务端通信** | 发指令、收状态（★ 本次改造核心） |
| **服务端协议编解码** | JSON 序列化/反序列化 |
| **高德定位 SDK** | `AMapLocationClient`（位置会上报高德服务器） |
| **高德地图 SDK** | `MapView` 初始化、隐私合规、`setApiKey` |

### ❌ 不算外部（留在原处）

| 项 | 说明 |
|---|---|
| DataStore 本地存储 | 设置、作业记录 —— 存手机本地 |
| Android 权限 API | 只问系统，不对外发数据 |
| 全部 Compose 界面 | 纯展示 |
| 模拟数据（Fake） | 内存中的假设备，不联网 |
| **小车协议** | ⚠️ **不再是手机的事**，属服务端↔小车之间的协议 |

> **关键简化**：手机不再解析小车协议（ESP32 的 `/status` JSON）。
> 手机只认**服务端协议**。小车协议是服务端与 ESP32 之间的约定。

## 3. 协议选型（关键决策）

| 方案 | 实时性 | 复杂度 | 适用 |
|---|---|---|---|
| **A. HTTP 轮询** | 1Hz（够用） | ⭐ 最简单 | 先跑通、演示 |
| **B. WebSocket** | 毫秒级推送 | 中 | 遥控体验好，推荐最终形态 |
| C. MQTT | 毫秒级 | 高（要 broker） | 大规模 IoT |

### 建议：分两步走

1. **先用 A（HTTP 轮询）跑通全链路**
   - 服务端实现简单（几个 REST 接口）
   - APP 现有代码几乎不用改（本来就是 1Hz 轮询）
2. **再升级 B（WebSocket）**
   - 遥控保持包改推送，延迟更低、省流量
   - APP 侧预留接口形状，替换实现即可

遥控场景下指令下发用 HTTP 也行（300ms 保持包），只是状态回传靠轮询略浪费。**先 A 后 B 风险最低。**

## 4. `external/ExternalApi.kt` 设计

唯一对外出口。UI / ViewModel **不直接 import**，只通过 `core/data` 的接口访问。

```kotlin
package com.example.myapplication.external

// ═══════════════════════════════════════════════════
// 区块 1：对外配置（换服务端 / 开关都在这里）
// ═══════════════════════════════════════════════════
object ExternalConfig {
    var serverUrl = "http://192.168.1.100:8080"   // 服务端 IP（可输入）
    var enabled = true                             // false = 纯展示模式
    const val CONNECT_TIMEOUT_MS = 1500
    const val READ_TIMEOUT_MS = 2000
}

// ═══════════════════════════════════════════════════
// 区块 2：服务端通信（★ 核心）
// ═══════════════════════════════════════════════════
object ServerApi {
    suspend fun sendCommand(cmd: ServerCommand): Result<ServerAck>
    suspend fun fetchDeviceStatus(): Result<ServerDeviceStatus>
    // 预留 WebSocket：
    // suspend fun openStream(onStatus: (ServerDeviceStatus) -> Unit)
}

// ═══════════════════════════════════════════════════
// 区块 3：服务端协议编解码
// ═══════════════════════════════════════════════════
object ServerJson {
    fun parseStatus(raw: String): ServerDeviceStatus
    fun parseAck(raw: String): ServerAck
}

// ═══════════════════════════════════════════════════
// 区块 4：高德定位
// ═══════════════════════════════════════════════════
object LocationApi {
    fun start(onFix: (LocationFix) -> Unit)
    fun stop()
}

// ═══════════════════════════════════════════════════
// 区块 5：高德地图 SDK 边界
// ═══════════════════════════════════════════════════
object MapSdkApi {
    fun initIfNeeded(context: Context)   // 隐私合规 + setApiKey
}

// ═══════════════════════════════════════════════════
// 区块 6：对外数据模型（与内部模型解耦）
// ═══════════════════════════════════════════════════
sealed class ServerCommand {
    data class Move(val dir: String) : ServerCommand()      // fwd/back/left/right
    object Stop : ServerCommand()
    object Estop : ServerCommand()
    object Resume : ServerCommand()
    data class StartTask(val kind: String, val targetM: Double) : ServerCommand()
    object Recover : ServerCommand()
    object Cancel : ServerCommand()
    data class Light(val mode: String) : ServerCommand()    // off/on/blink
    object ResetOdo : ServerCommand()
}

data class ServerAck(val accepted: Boolean, val cmdId: String? = null, val reason: String? = null)

data class ServerDeviceStatus(/* 服务端约定字段 */)
```

**要点**：
- 小车协议的字段名、路由**不在手机侧出现**，服务端负责转译
- `ExternalConfig.enabled = false` 时一律返回失败，UI 自动走模拟/静态展示
- 内部模型 `DeviceSnapshot` / `VehicleUiState` / 所有页面**完全不变**

## 5. 改造后目录结构

```
com/example/myapplication/
├── external/                         ⭐ 新增：唯一对外边界
│   └── ExternalApi.kt                 服务端通信 + 高德 SDK + 协议编解码
│
├── core/data/                        改造：变成「数据门面」
│   ├── device/DeviceRepository.kt     接口保留（UI 不感知）
│   ├── device/FakeDeviceRepository.kt ← 保留（模拟模式，界面可展示）
│   ├── device/ServerDeviceRepository.kt  ← 新：调 ServerApi（替代 HttpDeviceRepository）
│   ├── location/…                     同上
│   └── record/  prefs/                ← 不动（本地存储）
│
├── core/ui/                          不动（静态展示组件）
└── feature/                          不动（所有页面）
```

**数据流**：
```
UI 页面 → DeviceRepository 接口 ┐
                                 ├─→ ExternalApi.kt  🚪 唯一出口
        FakeDeviceRepository ────┘      ├─→ 服务端
                                        ├─→ 高德定位
                                        └─→ 高德地图
```

## 6. 三种运行模式（保证「至少可以展示」）

| 模式 | 行为 | 用途 |
|---|---|---|
| `REAL` | 真连服务端（走 `ExternalApi`） | 现场作业 |
| **`SIMULATE`** ⭐默认 | 用 Fake 数据，界面全流程可点 | 演示 / 无服务端开发 |
| `DISPLAY` | 不发任何外部请求，界面纯静态展示 | 断网 / 汇报展示 |

**保证**：`SIMULATE` / `DISPLAY` 模式下**代码路径完全不经过 `ExternalApi`**：
- 不需要连局域网
- 不会因网络问题闪退
- 地图 / 状态卡 / 进度条照样渲染（用模拟值）

## 8. 好处与新增关注点

### ✅ 好处
- 手机正常上网，**地图直接出图**，不用 AP+STA 折腾
- 天然支持多车（服务端按 deviceId 路由）
- 小车可离线缓存、断线重传（服务端负责）
- 安全性好：手机不直连小车，服务端可鉴权/限流

### ⚠️ 新增关注点

| 项 | 说明 |
|---|---|
| **延迟双跳** | 手机→服务端→小车，遥控响应比直连慢；指令要打时间戳 |
| **遥控保持包转发** | 300ms 一次，服务端要扛得住 |
| **鉴权** | 服务端建议加 token，否则局域网内谁都能控车 |
| **服务端单点** | 挂了全挂，需要「服务端不可达」的降级提示 |
| **IP 配置** | APP 填的是**服务端 IP**，不是小车 IP |
| **错误语义区分** | 「服务端不可达」≠「小车失联」，UI 要分开提示 |

## 附 A：手机 ↔ 服务端 接口协议草案（供服务端参考）

> ⚠️ **草案，未定稿**。若服务端已有接口，以服务端为准。

### A.1 指令下发

```
POST /api/v1/device/command
Content-Type: application/json

{
  "deviceId": "TC-001",          // 多车时必填
  "type": "move | stop | estop | resume | task_start | task_cancel | recover | light | odo_reset",
  "dir": "fwd",                   // type=move 时
  "kind": "fixed_distance",       // type=task_start 时
  "targetM": 30,                  // type=task_start 时
  "mode": "blink",                // type=light 时
  "ts": 1760083200000             // 客户端时间戳，便于服务端测延迟
}

→ 200
{ "accepted": true, "cmdId": "c-123" }

→ 200/400
{ "accepted": false, "reason": "estop_locked" }
```

### A.2 状态拉取（HTTP 轮询）

```
GET /api/v1/device/status?deviceId=TC-001

→ 200
{
  "deviceId": "TC-001",
  "mode": "idle",                 // idle | manual | auto | safe_stop
  "motion": "stopped",            // stopped | moving | fault
  "estopLocked": false,
  "stopSource": "manual",         // manual|estop|link_loss|encoder|deviation|timeout
  "light": "off",                 // off | on | blink
  "task": {
    "id": "t-1", "kind": "fixed_distance", "source": "app",
    "targetM": 30, "traveledM": 12.4,
    "state": "running",           // idle|running|done|failed|canceled
    "stage": null, "resultNote": null
  },
  "odo": { "leftPulse": 6200, "rightPulse": 6180,
           "traveledM": 12.4, "speedMps": 0.25, "diffPulse": 20 },
  "gps": { "lat": 39.9088, "lng": 116.3975, "acc": 5.0, "state": "fixed" },  // 可选
  "ts": 1760083200000
}
```

### A.3 错误码

| reason | 含义 |
|---|---|
| `estop_locked` | 急停锁定中 |
| `task_running` | 已有任务运行中 |
| `param_out_of_range` | 参数超范围（距离 10–100 米） |
| `device_offline` | 小车不在线 |
| `server_busy` | 服务端忙 |

### A.4 状态语义（服务端需保证）

- **移动指令看门狗**：800ms 无新 `move` 自动停车（APP 每 300ms 发保持包）
- **急停优先**：`estop` 后拒绝一切运动指令，直到 `resume`
- **任务不可重入**：`task_start` 时已有任务跑 → 返回 `task_running`
- **灯光独立**：停车/急停/失联不自动关灯；关灯不解除急停

## 附 B：风险与降级

| 场景 | 处理 |
|---|---|
| 服务端不可达 | UI 显示「服务端不可达，请检查网络/服务端」，禁用运动操作 |
| 小车失联（服务端报 `device_offline`） | UI 显示「设备已断开／状态未确认」 |
| 指令超时无回包 | 标「结果未知」，**不自动重发**，提示先查状态 |
| 服务端重启 | APP 重新拉状态，不重放断线前指令 |
