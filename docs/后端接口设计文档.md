## 1. 总体架构与交互全景

### 1.1 三层架构（沿用现有方案）

```
┌────────────┐   ①指令/业务请求   ┌────────────┐   ③指令转发   ┌────────────┐
│  手机 APP  │ ────────────────→ │   服务端    │ ───────────→ │ 小车 ESP32 │
│  (Android) │                   │ (局域网/云) │              │            │
│            │ ←──────────────── │            │ ←─────────── │            │
└────────────┘   ④状态/业务响应   └────────────┘   ②状态上报    └────────────┘
                                                （1Hz 或事件触发）
```

- 手机**不直连小车**；小车协议（附录 A）由服务端转译。
- 手机负责：本地存储（设置/记录缓存）、高德定位与地图渲染、界面逻辑。
- 服务端负责：鉴权、设备路由与在线状态、命令转发、状态聚合、记录/快照/预警/风险数据、视频中继。

### 1.2 数据流与频率

| 序号 | 方向 | 内容 | 频率 | 协议 |
|---|---|---|---|---|
| ① | 手机 → 服务端 | 控制指令（遥控/任务/急停/灯光…）、业务请求 | 事件触发；**遥控保持包 300ms** | HTTP POST |
| ② | 小车 → 服务端 | 设备状态（模式/运动/任务进度/里程/GPS…） | 1Hz | 服务端与小车约定（附 A） |
| ③ | 服务端 → 小车 | 转发的控制指令 | 同 ① | 同 ② |
| ④ | 服务端 → 手机 | 状态查询（轮询 1Hz）、业务响应 | 1Hz / 事件 | HTTP GET/POST |

> 实时性说明：先全部用 **HTTP 轮询**跑通（与现有 APP 1Hz 轮询一致），协议形状预留升级
> （后续可把「状态查询」换成 SSE `text/event-stream` 或 WebSocket 推送，**不改变任何字段定义**）。

### 1.3 界面 → 后端需求速览（详细对照见附录 C）

| 界面（静态现状） | 现数据来源 | 接入后端后需要的接口 |
|---|---|---|
| 登录页 | ✅ 已接服务端登录（默认账号 demo/123456 已预填，可跳过） | `POST /auth/login`（第 3 节） |
| 设备连接页（下拉、状态、连接/断开、添加设备弹窗[编号/扫码/删除]） | Fake 设备 / 本机 DataStore | 设备台账与绑定接口（第 4 节）+ 状态接口（第 5 节） |
| 首页「当前设备 / 正在执行的任务」 | 本机状态 | 状态接口（第 5 节） |
| 任务发布页（路线设计→发布） | 本机表单 | `POST /device/command {task_start}`（第 7 节） |
| 任务执行页（进度、手动干预、停止、核验、上传、**实时视频占位**、**捕捉快照**） | 状态轮询 + 占位 | 命令（第 6 节）+ 状态（第 5 节）+ **视频流**（第 11 节）+ 快照（第 9 节）+ 记录上传（第 8 节） |
| 记录页（本机记录 + 「云端记录」置灰卡） | 仅本机 | 记录上传与**云端查询**（第 8 节） |
| 风险页 / 事故详情页（照片/视频占位） | FakeRiskRepository | `GET /risks`（第 12 节，**含作业人员上传的快照登记项**）；事故照片/视频 URL（第 11/12 节） |
| 地图页 / 发布页地图（手机位置 + 小车位置） | 高德 SDK + 状态估算 | 手机定位：**本地高德，不经后端**（第 14 节）；小车 GPS 随状态返回 |
| 设置页「检查更新 / 帮助与反馈 / 切换账号 / 退出登录」 | 演示弹窗 | 版本检查、反馈、登出接口（第 13 节） |
| 设备信息页（编号/固件/连接方式；电池、OTA 置灰） | 状态快照 | 设备详情接口（第 4 节）；OTA 预留 |

### 1.4 三种运行模式（沿用架构方案）

| 模式 | 行为 | 用途 |
|---|---|---|
| `REAL` | 全部请求走本服务端 | 现场作业 |
| `SIMULATE`（默认） | 用 Fake 数据，界面全流程可点，不请求服务端 | 演示 / 联调未完成 |
| `DISPLAY` | 不发任何请求，界面静态展示 | 汇报展示 |

## 2. 通用约定

### 2.1 基础

| 项 | 约定 |
|---|---|
| 基地址 | 服务端局域网 IP（架构方案：`http://192.168.1.100:8080` 可配置），如 `http://<服务器IP>:8080` |
| 接口前缀 | `/api/v1` |
| 编码 | UTF-8，`Content-Type: application/json; charset=utf-8` |
| 时间 | **epoch 毫秒（Long）**，所有 `xxxAt/ts/xxxAt` 字段 |
| ID | 字符串。服务端生成的业务单号建议 `srv-`/`snap-`/`warn-` 前缀 |
| 坐标系 | 风险/事故：**GCJ-02（高德）**；车端 GPS：**WGS-84**（APP 已实现转换，见附录 B.6） |
| 认证 | `Authorization: Bearer <accessToken>`（登录后的全部接口）；视频流可用查询参数 `token`（见 11.3） |
| 连接超时/读超时 | 建议 APP 侧 connect 1500ms / read 2000ms（与现状一致）；上传类 3000/5000ms |

### 2.2 响应格式（两种，均不使用包一层大信封）

**A. 业务接口**——成功直接返回数据对象（HTTP 200/201），失败返回错误体：

```json
HTTP 400
{
  "error": {
    "code": "param_out_of_range",
    "message": "第 1 段：前进距离须在 1~50 米",
    "detail": { "field": "segments[0].value" }
  }
}
```

**B. 实时控制接口**（状态/命令，低延迟路径）——沿用《三层通信架构方案》附 A 草案的直出风格：

```json
// 命令应答（HTTP 200）
{ "accepted": true, "cmdId": "c-123" }
{ "accepted": false, "reason": "estop_locked" }
```

> 约定：`accepted:false` 表示**业务性拒绝**（HTTP 仍为 200，`reason` 原样展示给用户）；
> 网络/服务端故障才用 4xx/5xx + error 体。APP 现有代码即按此语义解析。

### 2.3 通用错误码（HTTP 层）

| HTTP | code | 含义 | APP 侧处理 |
|---|---|---|---|
| 400 | `bad_request` | 参数缺失/格式错误 | 展示 message |
| 401 | `token_expired` | accessToken 过期 | 用 refreshToken 自动刷新后重放（仅一次性业务请求）；失败 → 回登录页 |
| 401 | `bad_credentials` | 账号或密码错误 | 登录页提示 |
| 403 | `forbidden` | 无权限操作该设备 | 提示无权限 |
| 404 | `not_found` | 资源不存在（设备/记录/事故） | 提示并回到列表 |
| 409 | `conflict` | 冲突（如重复绑定） | 展示 message |
| 429 | `too_many_requests` | 限流（状态轮询除外） | 指数退避重试 |
| 500 | `server_error` | 服务端内部错误 | 提示稍后重试 |
| 503 | `server_busy` / `device_offline` | 服务端忙 / 小车不在线 | 分别提示（见第 17 节） |

### 2.4 幂等与重试

| 请求类别 | 幂等策略 | 自动重试 |
|---|---|---|
| 运动/任务类命令（move/stop/estop/task_start/…） | 不支持自动幂等，**绝不自动重发** | ❌ 超时标「结果未知」，先查状态，人工决定 |
| 记录/快照/预警上传 | 客户端携带 `Idempotency-Key: <客户端记录 id>`，服务端按（用户, key）去重 | ✅ 可重试（指数退避，间隔 5s/15s/60s） |
| 查询类（status/list/details） | 天然幂等 | ✅ 可重试 |

### 2.5 分页（列表类接口）

```
GET /api/v1/tasks?page=1&size=20
→ 200 { "items": [...], "page": 1, "size": 20, "total": 137 }
```

## 3. 认证与账号（登录页）

> **当前实现**：登录页已接服务端登录（`HttpAuthRepository`）；token 存内存（持久化/自动刷新为后续增强），
> 各 HTTP 仓库经 `Authorization: Bearer` 携带；**设备信息按登录用户获取**（第 4 节）。
> **调试默认账号 `demo / 123456`**（登录页已预填；Mock 服务端内置并绑定演示设备）。
> 「跳过登录」保留：不取 token，Mock 宽松模式按默认用户 demo 处理；正式服务端应返回 401。

### 3.1 登录

```
POST /api/v1/auth/login
```
请求：
```json
{
  "username": "op001",
  "password": "******",
  "client": "android",
  "appVersion": "1.0",
  "deviceModel": "Xiaomi 14"
}
```
响应 `200`：
```json
{
  "token": "eyJhbGciOiJIUzI1NiIs...",
  "refreshToken": "eyJhbGciOiJIUzI1NiIs...",
  "expiresIn": 7200,
  "user": { "id": "u-1001", "name": "张三", "role": "operator", "phone": "138****0000" }
}
```
失败：`401 {"error":{"code":"bad_credentials","message":"用户名或密码错误"}}`

### 3.2 刷新 token

```
POST /api/v1/auth/refresh
{ "refreshToken": "eyJ..." }
→ 200 { "token": "eyJ...", "refreshToken": "eyJ...", "expiresIn": 7200 }
```

### 3.3 当前用户信息

```
GET /api/v1/auth/profile      （Bearer）
→ 200 { "id": "u-1001", "name": "张三", "role": "operator", "phone": "138****0000" }
```

### 3.4 登出（设置页「退出登录 / 切换账号」）

```
POST /api/v1/auth/logout      （Bearer）
→ 204
```
APP 侧同时清除本地 token，回到登录页。

## 4. 设备台账与绑定（连接页 / 添加设备 / 设备信息页）

> 现状：设备列表 = 内置 Fake 设备 + 本机 DataStore 登记（`DeviceRegistryRepository`）；
> 「添加设备」支持输入编号/扫码，可手动删除；连接判定依赖实时状态（第 5 节）。
> 接入后：**台账由服务端管理**（绑定关系+在线态+电量+固件版本），本机 DataStore 仅作离线缓存。
>
> **按登录用户过滤**：`GET /devices` 只返回**当前登录账号绑定**的设备。APP 登录成功后调用
> `vm.reloadDevices()` 刷新列表（登录前拉取的是未鉴权/默认账号的数据）。
> Mock 行为：默认账号 demo 绑定 TC-001/TC-002；其他新账号列表为空，绑定（bind）后才可见。

### 4.1 设备列表（连接页下拉）

```
GET /api/v1/devices       （Bearer）
```
响应 `200`：
```json
{
  "devices": [
    {
      "deviceId": "TC-001",
      "name": "三角警示牌一号车",
      "bound": true,
      "online": true,
      "started": true,
      "available": true,
      "batteryPercent": 86,
      "fw": "0.3.1",
      "lastSeenAt": 1760083200000
    },
    {
      "deviceId": "TC-002",
      "name": "三角警示牌二号车",
      "bound": true,
      "online": false,
      "started": false,
      "available": false,
      "batteryPercent": null,
      "fw": "0.3.0",
      "lastSeenAt": 1760070000000
    }
  ]
}
```
字段映射（对应界面「是否开始 / 是否可用 / 电量」三项）：
- `started` = 已上电/启动；`available` = 可用于作业（未被占用、无故障）；
- `batteryPercent`：`null` = 无来源（界面显示「未知」，对应 C 阶段验收项）；`batteryText` 由 APP 生成。

### 4.2 扫码/编号绑定设备（添加设备弹窗）

二维码内容约定（二选一，**推荐第 2 种，可扩展**）：

```
方式1（纯编号）：TC-001
方式2（JSON，向后兼容扫描任意纯文本编号）：
  { "deviceId": "TC-001", "sn": "ESP32-8F2A11", "model": "triangle-car-v1" }
```

```
POST /api/v1/devices/bind       （Bearer）
{ "deviceId": "TC-001" }
→ 201 { "device": { "deviceId": "TC-001", "name": "三角警示牌一号车", "bound": true } }
```
错误：
- `404 {"error":{"code":"unknown_device","message":"该编号未在平台注册，请核对设备铭牌"}}`
- `409 {"error":{"code":"already_bound","message":"该设备已被其他账号绑定"}}`

### 4.3 解绑设备（弹窗内「删除」）

```
DELETE /api/v1/devices/{deviceId}/bind      （Bearer）
→ 204
```
约定：内置演示设备不可解绑 → `400 {"error":{"code":"cannot_unbind_builtin","message":"内置演示设备不可删除"}}`。

## 5. 设备实时状态

> APP 唯一事实源：**一切「已连接/完成/停车/电量」以本接口返回为准，APP 不自行推断**。
> 1Hz 轮询；连接判定：**只有收到 HTTP 200 且字段有效的状态，才显示「已连接」**。

### 5.1 状态查询

```

    "stage": null,
    "resultNote": null,
    "heading": 90.0,
    "segments": [
      { "action": "fwd",  "value": 20.0, "state": "done",    "progress": 1.0 },
      { "action": "turn", "value": 90.0, "state": "running", "progress": 0.4 },
      { "action": "fwd",  "value": 20.0, "state": "pending", "progress": 0.0 }
    ]
  },
  "odo": {
    "leftPulse": 6200, "rightPulse": 6180,

  },

```

### 5.2 字段说明（与 APP 模型一一对应）

| 字段 | 类型 | 说明 |
|---|---|---|
| `mode` | string | `standby` 待命 / `manual` 手动 / `auto` 自动 / `safe_stop` 安全停止 |
| `motion` | string | `idle` 静止 / `moving` 行驶中 / `fault` 故障 |
| `estopLocked` | bool | 急停锁定中（锁定时拒绝一切运动指令） |
| `stopSource` | string | `none` / `manual` / `estop` / `link_loss` / `encoder` / `deviation` / `timeout` |
| `light` | string | `off` / `on` / `blink`（与运动分离：停车/急停/失联不自动关灯） |
| `task.state` | string | `idle` / `running` / `done` / `failed` / `canceled` |
| `task.kind` | string | `fixed_distance` / `manual` / `one_touch` / `recover` |
| `task.source` | string | `app` 手机发起 / `button` 车身实体按钮发起（APP 只读取，不干预） |
| `task.segments[].state` | string | `pending` / `waiting_confirm` / `running` / `done` / `failed` / `skipped` |
| `task.segments[].progress` | number | 段内进度 0~1（旧固件无 segments 字段时省略 → APP 退化为整体进度） |
| `task.heading` | number | 当前航向角（度，正北=0） |
| `task.stage` | string? | 一键布置阶段：`lighting`/`countdown`/`moving`/`parked`（无则 null） |
| `odo.*` | number | 编码器估算：脉冲数/里程(米)/速度(m/s)/左右脉冲差 |
| `gps` | object? | **WGS-84**（见附录 B.6）；无 GPS 模块**省略整个字段**；`state`：`fixed`/`no_fix`/`absent` |
| `batteryPercent` | int? | `null` = 无来源（界面置灰/显示未知） |
| `tilt` / `obstacle` | bool? | 预留传感器；`null` = 无来源 |
| `ts` | long | 设备侧时间戳（服务端透传小车时间） |

> 联调 Mock 行为：默认发送 `gps` 块（WGS-84，位置随里程 1Hz 实时变化，**锚定于 APP 上报的手机位置
> `&lat=&lng=`**，无上报时用默认基准点）；置 Mock 顶部 `EMIT_GPS=false` 可验证「无 GPS → 行程估算」降级路径。

### 5.3 轮询与「非实时」判定（APP 侧行为，服务端需知晓）

- APP 每 **1000ms** 调一次本接口；连接超时/失败 → 显示「已断开／状态未确认」，**禁用运动操作**；
- 距上一次成功超过 **3 秒** → 界面标注「非实时」；
- 失败期间**不缓存命令**（见第 15 节「离线命令禁排队」）；
- 多车：`deviceId` 参数选择目标；同时只轮询当前选中设备。

### 5.4 可选升级：SSE 推送（字段不变）

```
GET /api/v1/device/stream?deviceId=TC-001      （Bearer，Accept: text/event-stream）
event: status
data: { ...与 5.1 完全相同的 JSON... }
```
每 1s 推送一帧或状态变化时推送；断线由客户端重建。**上线时可先不做**。

## 6. 控制命令

> 覆盖：手动遥控（按住方向，300ms 保持包）、普通停车、急停、恢复、灯光、里程清零、分段确认。
> **命令语义 = 一次性请求-应答**；APP 侧维护「命令五层票据」（见 6.3），超时一律标「结果未知」，**不自动重发**。

### 6.1 通用命令接口

```
POST /api/v1/device/command      （Bearer）
```

请求通用字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `deviceId` | string | ✅ | 目标小车 |
| `type` | string | ✅ | 见 6.2 全表 |
| `ts` | long | ✅ | 客户端毫秒时间戳（服务端可据此测端到端延迟） |

响应（HTTP 200）：
```json
{ "accepted": true, "cmdId": "c-7f3a" }
{ "accepted": false, "reason": "estop_locked" }
```

`cmdId`：服务端本次指令单号，用于日志追踪；APP 记录进命令票据。

### 6.2 命令类型全表

| type | 附加字段 | 说明 | 对应界面 |
|---|---|---|---|
| `move` | `dir`: `fwd`/`back`/`left`/`right` | 按住移动；APP 每 **300ms** 发一次保持包（**必须 < 车端 800ms 看门狗**） | 任务执行页·手动干预弹窗、调试页 |
| `stop` | — | 普通停车：停运动，不锁定、不关灯 | 手动干预「停止」 |
| `estop` | — | 急停：最高优先、无二次确认、进入锁定 | 全局急停（车身实体按钮另有硬件急停，不由 APP 替代） |
| `resume` | — | 人工现场核查后恢复待命，不续跑任务 | 急停后恢复 |
| `light` | `mode`: `off`/`on`/`blink` | 灯光三模式互斥；终态以 status 为准 | 灯光控制 |
| `task_start` | 见 6.4（两种形态） | 启动任务（发布即执行） | 发布页 |
| `task_cancel` | — | 取消当前任务，剩余路段标「未执行」 | 执行页「停止并取消任务」 |
| `segment_confirm` | — | 分段确认模式：确认执行当前段 | 执行页「执行本段」 |
| `recover` | — | 自动回收：小车返回作业人员位置 | 执行页「回收小车」 |
| `odo_reset` | — | 里程清零（仅静止且无任务时允许） | 运行数据 |

示例：
```json
// 遥控（保持包，每 300ms 一次）
{ "deviceId": "TC-001", "type": "move", "dir": "fwd", "ts": 1760083200000 }

// 急停
{ "deviceId": "TC-001", "type": "estop", "ts": 1760083200000 }

// 灯光
{ "deviceId": "TC-001", "type": "light", "mode": "blink", "ts": 1760083200000 }
```

### 6.3 命令五层票据 ↔ HTTP 映射（APP 侧展示「第 X/5 步」）

| 层 | 票据状态 | 判定来源 |
|---|---|---|
| 1 | 已发出 | APP 本地（HTTP 请求发出） |
| 2 | 设备已接收 | HTTP 200 + `accepted:true`（语义：服务端已受理**且设备在线**；设备离线必须返回 `accepted:false, reason=device_offline`） |
| 3 | 正在执行 | `/device/status` 轮询：任务 `state=running` / 运动 `moving` |
| 4 | 设备报告完成 | 轮询：`state=done`（或 failed → 失败熔断） |
| 5 | 人工已核验 | APP 内人工核验（第 8 节随记录上传） |

超时/网络错误：HTTP 层失败保留「结果未知」票据；**绝不自动重发运动指令**。

### 6.4 任务启动（task_start）两种形态

```json
// 形态1：单段快捷（定距布置 targetM 由表单给定）
{ "deviceId": "TC-001", "type": "task_start",
  "kind": "fixed_distance", "targetM": 20.0, "ts": 1760083200000 }

// 形态2：整条路线一次性下发（推荐，路线在车端离线闭环执行）
{ "deviceId": "TC-001", "type": "task_start",
  "kind": "manual",
  "mode": "auto",                 // auto 全自动驾驶 / segment_confirm 分段确认
  "light": "blink",               // 任务期间灯光
  "segments": [
    { "action": "fwd",  "value": 20.0 },
    { "action": "turn", "value": 90.0 },
    { "action": "fwd",  "value": 20.0 }
  ],
  "ts": 1760083200000 }
```

参数范围（**服务端与 APP、车端同一套校验**，越界回 `param_out_of_range`）：

| 项 | 范围 |
|---|---|
| 单段前进 | 1 ~ 50 米 |
| 单段转向 | 5 ~ 180 度（符号：负=左转，正=右转） |
| 段数 | 1 ~ 10 段 |
| 路线总长 | ≤ 200 米 |
| 任务名/备注 | ≤ 30 / 100 字（APP 侧校验） |

### 6.5 拒绝原因码（reason）总表

| reason | 中文含义（APP 原样展示） |
|---|---|
| `estop_locked` | 急停锁定中，禁止运动指令 / 请先现场核查后恢复 |
| `task_running` | 已有任务运行中，禁止重复启动 / 手动抢占 |
| `route_empty` | 路线不能为空 |
| `too_many_segments` | 路段不能超过 10 段 |
| `param_out_of_range` / `segment_out_of_range` | 参数超出允许范围 |
| `not_locked` | 当前未处于急停锁定状态（resume 时） |
| `no_task` | 当前无运行中任务（segment_confirm 时） |
| `not_waiting_confirm` | 当前没有待确认的路段 |
| `already_home` | 小车已在作业人员位置，无需回收 |
| `busy` | 自动运动中，禁止计数清零 |
| `device_offline` | 小车不在线（服务端判定） |
| `server_busy` | 服务端忙，请稍后重试 |

## 7. 任务：发布·执行·取消·回收

### 7.1 发布（发布即执行）

- 界面：任务发布页（路线设计 → 预检勾选 → 「发布任务（立即执行）」）。
- 交互：`POST /api/v1/device/command {type:"task_start", kind, mode, light, segments}`（见 6.4）。
- 发布前 APP 本地校验（与 6.4 范围表一致）：路线非空、段数/参数/总长、任务名长度、预检勾选。
- 发布成功后 APP 立即跳转执行页（无启动按钮），后续进度全部来自第 5 节轮询。

### 7.2 执行监控

- 数据源：第 5 节 `task.segments[]`（进度条、当前段、待确认段、航向）。
- 分段确认模式：`task.segments[].state = waiting_confirm` 时显示「执行本段」按钮 → `segment_confirm`。
- 失败熔断：`task.state=failed` → 展示失败原因（`resultNote`）、剩余段标 `skipped`。

### 7.3 取消 / 重新下发 / 回收

| 动作 | 接口 |
|---|---|
| 停止并取消任务 | `POST /device/command {type:"task_cancel"}` |
| 下发失败后「重新下发」 | 用同一份路线再次 `task_start`（走同一校验门） |
| 回收小车 | `POST /device/command {type:"recover"}`（车端按里程返航至起点） |

### 7.4 任务云端记录（发布时登记，可选）

> 若服务端希望**任务一发布就有云端记录**（不等结束后上传），可在发布成功后再调：

```
POST /api/v1/tasks/register      （可选，预留）
{ "clientId": "本地记录id", "deviceId": "TC-001", "name": "自动布置",
  "kind": "manual", "mode": "auto", "segments": [...], "startedAt": 1760083200000 }
→ 201 { "id": "srv-xxxx" }
```
结束后的结果仍走第 8 节上传（服务端按 `clientId` 合并）。

## 11. 视频流

> 现状：任务执行页「实时视频」为演示占位（未接车载摄像头）；事故详情页照片/视频为占位。
> **全部方案基于 HTTP**，三种形态按带宽/设备能力选择：
>
> **联调约定（当前实现）**：**所有视频共用服务端同一路视频流**（实时视频与各「事故视频」同址）；
> APP 侧已接 `MjpegStreamView`（无第三方库，multipart/x-mixed-replace 逐帧解码）播放；
> Mock 服务端提供 10fps 时间驱动的动画帧（天色轮转 / 滚动道路虚线 / 往返三角警示牌），
> **快照图片即从该流按当前帧截取**（§9）。接真实视频源后仅替换服务端实现，APP 不动。

### 11.1 方案总览（均基于 HTTP）

| 方案 | 端点形态 | 优点 | 适用 |
|---|---|---|---|
| **A. MJPEG over HTTP**（推荐先行） | `multipart/x-mixed-replace` 持续响应 | ESP32-CAM 原生输出，链路最短、实现最简单 | 局域网演示、低分辨率 |
| **B. HLS** | `.m3u8` + `.ts` 分片（HTTP 拉取） | 兼容性好（ExoPlayer 原生支持）、可适配弱网 | 服务端 ffmpeg 转封装后 |
| **C. HTTP-FLV** | 长连接 chunked | 延迟低于 HLS | 可选，服务端支持时 |

### 11.2 实时视频（任务执行页）

```
# A. MJPEG 中继（主方案）
GET /api/v1/device/video/stream?deviceId=TC-001&token=<accessToken>&w=640&fps=10
→ 200 Content-Type: multipart/x-mixed-replace; boundary=frame
   （持续输出 JPEG 帧；服务端从车端拉流 # 再原样转发）

# B. HLS（服务端转封装，可选）
GET /api/v1/device/video/live.m3u8?deviceId=TC-001&token=<accessToken>
GET /api/v1/device/video/seg/<seq>.ts?token=<accessToken>

# C. 单帧抓拍（低带宽/快照用）
GET /api/v1/device/video/snapshot.jpg?deviceId=TC-001&token=<accessToken>
→ 200 image/jpeg
```

约定：
- **鉴权**：播放器普遍不能自定义 Header，允许 `?token=` 查询参数（服务端建议签发**短时效流 token**，5 分钟）；
- 参数 `w`（宽）/`fps`（帧率）由服务端向车端透传或降采样，默认 640×480@10fps；
- 小车侧常为 `GET http://<车IP>/stream`（MJPEG）与 `GET /snapshot.jpg`（服务端与小车约定，见附 A.4）。

### 11.3 APP 侧接入建议

| 内容 | 建议实现 |
|---|---|
| MJPEG | `WebView` 直接加载流地址（最简单）；或自实现 multipart 解析 + `Bitmap` 刷帧 |
| HLS / MP4 | ExoPlayer（`androidx.media3`），支持点播与直播 |
| 降级 | 拉流失败/超时 → 显示占位图与「视频暂不可用」，重连采用 1s/2s/5s 退避；**视频可用性与状态轮询相互独立**（无摄像头时 capabilities.camera=false，整卡置灰） |
| 带宽 | ESP32 带宽有限：单路 640×480@10fps 约 1~2 Mbps；不并发多路视频 |

### 11.4 事故视频点播（事故详情页）

（服务端返回可直连的 HTTP 地址，MP4 或 HLS 均可；APP 用 ExoPlayer / 图片加载库渲染）。

## 15. 服务端需保证的行为语义

> 以下语义 APP 与车端已按此实现/约定，**服务端在中间转发时不得破坏**：

1. **移动看门狗**：APP 遥控每 300ms 发 `move` 保持包；车端 800ms 无新指令自动停车。
   服务端转发必须**及时、直通、不合并、不排队**（转发延迟建议 < 100ms）。
2. **急停优先**：`estop` 立即转发且优先于其余指令（可插队）；急停后拒绝一切运动指令直到 `resume`。
3. **任务不可重入**：已有任务运行中，`task_start` 必须回 `accepted:false, reason=task_running`。
4. **灯光独立**：停车/急停/失联**不自动关灯**；关灯不解除急停。
5. **结果未知即未知**：指令超时/无回包，语义为「可能已到达」，**不得代为重发运动命令**。
6. **离线命令禁排队**：设备离线时命令直接拒绝（`device_offline`），**不缓存、不重连后补发**。
7. **状态即事实**：所有"完成/停止/模式"以车端上报为准，服务端只做透传/聚合，不推断、不伪造。
8. **时间戳**：透传 `ts/deviceTs`，便于端到端延迟统计。

## 17. 降级与容错

| 场景 | UI/行为 |
|---|---|
