## 1. 产品概述

### 1.1 背景

道路临时管制、事故处置和施工养护时，作业人员需要沿预定路线快速布设多只智能锥桶。现有单设备作业模型只能表达“一台设备执行一条路线”，无法表达：

- 主桶与从桶的角色、编队顺序；
- 主桶先启动、从桶逐级启动的协同链路；
- 每只桶独立的累计行程、目标行程、启动与上报结果；
- 多设备被同一事件占用时的互斥关系；
- 一次作业的整体完成判定与逐只现场核验。

因此需要新增“布设事件”这一业务对象，用一次事件承载多设备协同布设的完整会话，并提供可执行、可监控、可追溯的产品闭环。

### 1.2 产品定位

锥桶协同布设是面向道路作业现场的**多设备协同布设工具**：

- **设备侧**：1 个主桶 + 0～5 个从桶，按用户确定的编队顺序沿预定路线移动；
- **服务端**：作为协同状态机、设备占用、指令链路和审计记录的权威；
- **APP 侧**：负责设备绑定与选择、参数发布、状态展示、异常处置、现场核验和记录查看；
- **现场侧**：设备到达只是“设备报告到达”，必须由作业人员逐只核对实际位置/处置方式后，事件才可完成。

### 1.3 产品目标

| 编号 | 目标 |
|---|---|
| G-1 | 作业人员可在 APP 内创建一次锥桶协同布设事件，选择主桶与从桶并确定顺序 |
| G-2 | APP 可按 L、d 计算并展示每只桶的目标行程，参数不合法时禁止启动 |
| G-3 | 启动后严格按“主桶 → 从 1；从 1 → 主桶 → 从 2；……”的链路逐级启动，设备可并发移动 |
| G-4 | APP 可实时展示每只桶的编号、角色、顺序、连接、启动、行程、到达、指令与上报结果 |
| G-5 | 异常时 APP 显性告警，支持暂停、现场处置、安全重试、终止；系统不自动跳过、不自动重发运动指令 |
| G-6 | 全部设备到达或完成处置后，经现场人员逐只核验，事件才可完成，并形成可追溯记录 |

### 1.4 用户价值

| 价值 | 说明 |
|---|---|
| 降低协同成本 | 作业人员只需设置 L、d 和编队顺序，逐级启动由链路自动完成 |
| 状态可见 | 每只桶的连接、启动、行程、上报、到达、核验状态集中展示 |
| 异常可控 | 异常显性展示，支持暂停、现场处置、受控重试和人工跳过 |
| 安全可追溯 | 关键动作二次确认，人工跳过留痕，事件记录可回查 |
| 现场闭环 | 设备到达不等于完成，必须逐只核验后才能结束事件 |

### 1.5 本期范围

**包含**

- 锥桶设备连接页：主桶选择、从桶选择、套装候选、其他已绑定从桶、编队排序、绑定/解绑、占用校验；
- 锥桶作业主页：设备就绪状态、进行中事件入口、发布入口；
- 布设任务发布：事件信息、L/d 参数、可选 90° 路线转弯、布设预览、自动条件、人工确认、发布并启动；
- 布设执行：1Hz 聚合状态、每只桶状态卡、位置估算地图、主桶实时视频、异常展示、下一步提示；
- 控制动作：暂停全部、继续布设、重试当前步骤、受控人工跳过、终止事件；
- 单桶手动干预：暂停后对选中桶进行前进/后退/左转/右转点动；
- 现场核验：逐只核验通过/异常，全部通过后完成布设；
- 记录：锥桶布设记录列表、进行中事件卡片、详情查看；
- 服务端契约：设备台账、套装、绑定/解绑、布设事件创建/启动/查询/控制/核验/记录；
- 异常场景：设备离线、启动超时/被拒绝、上报丢失、设备被占用、网络失败、人工跳过。

**不包含**

| 不包含项 | 说明 |
|---|---|
| 三角架/三角牌单设备作业 | 本文档不再描述，也不作为锥桶流程的入口前置条件 |
| 主桶与从桶直连通信 | 统一经服务端中继，逻辑链路不变 |
| 自动路径规划、车道级定位、地图直线距离换算 | L/d 是沿预定路线的累计行程，不是地图直线距离 |
| 自动保持精确间距、自动纠偏、自动补位 | 行程反馈不代表精确间距，也不替代现场安全验收 |
| 自动跳过、自动重试运动指令 | 人工跳过和人工重试是受控例外，必须显式操作 |
| 多作业人员同时控制同一事件 | 本期单作业人员控制 |
| 套装后台管理界面 | 套装关系由平台预先维护，APP 只读取 |
| OTA、固件升级 | 不在本期 |
| 超过 5 处转弯、非 90° 转弯、弧线转向 | 本期仅支持最多 5 处固定 90° 左/右转 |
| 每只桶的 GPS 定位 | 地图位置是基于起点锚点和累计行程/朝向的估算 |

### 1.6 前置假设与依赖

| 编号 | 假设 | 影响 |
|---|---|---|
| A-1 | 锥桶是可移动设备，能按目标行程自主移动，并能上报**自本次启动时刻起**的累计行程 | 若设备只能上报上电累计行程，需要服务端保存启动基线并做差值 |
| A-2 | 设备具备角色属性（master/slave）和套装关联；套装由平台预先登记 | APP 只读取，不提供套装编辑；套装仅用于默认候选 |
| A-3 | 设备支持启动指令确认（ack）、指令 ID 去重、断链本地停车、急停优先 | 否则无法满足链路可靠性与安全要求 |
| A-4 | 设备能在本地检测“自身累计行程达到 d”的边沿并恰好上报一次 | d 较小时不能依赖 APP 轮询 |
| A-5 | 所有参演锥桶在启动前按编队顺序置于同一起始线，朝向布设方向 | 目标行程公式隐含共同起点；现场核验负责发现偏差 |
| A-6 | L、d 是沿路线累计行程标量；默认直行，支持最多 5 处 90° 左/右转 | 任意角度、超过 5 处、弧线转向不在本期 |
| A-7 | 服务端可保存事件会话与逐设备日志，并在重启后恢复 | 否则 APP 重连/服务端重启后无法继续展示与审计 |
| A-8 | 作业人员已登录，设备已绑定到当前账号/单位 | 未登录或未绑定设备无法进入布设流程 |
| A-9 | 手机与服务端网络可达；设备与服务端可达 | APP 不直连设备；网络异常时 APP 只能展示非实时状态 |

### 1.7 成功指标（建议）

当前版本未内置埋点统计，以下指标作为后续产品度量建议：

| 指标 | 定义 | 目标方向 |
|---|---|---|
| 布设任务完成率 | 完成事件数 / 启动事件数 | 提升 |
| 首次核验通过率 | 首次核验全部通过的事件数 / 进入待核验事件数 | 提升 |
| 异常处置完成率 | 异常事件中完成处置并结束的比例 | 提升 |
| 平均布设耗时 | 从启动到完成的中位时长 | 降低 |
| 人工跳过率 | 发生人工跳过的事件数 / 完成事件数 | 降低 |

## 2. 用户与使用场景

### 2.1 用户角色

| 角色 | 职责 | 不负责 |
|---|---|---|
| 作业人员（主要用户） | 绑定/选择设备、设置参数、现场预检、启动、暂停/继续、重试、人工跳过、现场核验、终止 | 不直接计算链路、不绕过服务端、不替代现场安全判断 |
| 现场安全负责人 | 确认起始线、编队顺序、转弯点及现场安全条件；参与异常处置决策 | 不直接操作 APP 的链路内部逻辑 |
| APP | 交互、即时校验、状态展示、控制动作发起、记录查看 | 不作为链路权威；不推测设备状态；不自动跳过/重发 |
| 服务端 | 设备台账、绑定/占用、事件会话、参数复验、链路编排、超时检测、幂等、审计、记录 | 不替代现场核验 |
| 主桶 | 启动后按自身行程触发从 1；收到从 k 上报后触发从 k+1；自身到达目标 | 不越级触发；不按自身行程代替从桶上报 |
| 从桶 | 收到启动指令后按目标行程移动；自身达到 d 时上报；到达目标 | 不直接向下一从桶发送启动指令 |
| 平台/后台 | 预登记套装关系、设备角色、归属 | 本期不提供 APP 内套装管理 |

### 2.2 典型使用场景

| 场景 | 用户目标 | 产品能力 |
|---|---|---|
| 交通事故现场临时封道 | 快速沿事故点后方布设锥桶，形成安全缓冲 | 主从编队、逐级启动、实时状态、异常处置 |
| 道路施工/养护作业 | 按施工区长度和间距要求布设锥桶 | L/d 参数、目标行程预览、路线转弯 |
| 临时交通管制 | 在指定车道/路段快速形成锥桶引导线 | 作业车道、事件记录、现场核验 |
| 夜间或低能见度作业 | 减少人员沿车道来回走动，降低暴露风险 | 一次启动、逐级自动触发、主桶视频 |
| 现场异常（设备离线/上报丢失） | 快速定位阻断点并安全处置 | 异常横幅、下一步提示、暂停、重试、受控跳过、终止 |

### 2.3 核心痛点与产品应对

| 痛点 | 现状 | 产品应对 |
|---|---|---|
| 多只桶需要人工依次启动 | 人员需要在车道上往返操作，效率低且危险 | 主桶到 d 自动触发从 1，从 k 到 d 上报后触发从 k+1 |
| 不知道每只桶走到哪 | 只能靠肉眼观察 | 每只桶展示目标/累计行程、启动/上报/到达状态 |
| 异常后不知道下一步 | 链路卡住后容易误操作 | 展示异常原因、当前阻断设备和下一步；禁止自动跳过/重发 |
| 设备被其他任务占用 | 到场后才发现设备不可用 | 设备列表展示占用/任务/离线原因；启动时服务端原子复验 |
| 设备到了但位置不对 | 行程反馈不等于现场安全验收 | 逐只现场核验，全部通过后才可完成 |
| 事后无法追溯 | 缺少统一记录 | 服务端记录事件、设备、链路步骤、异常、跳过和核验结果 |

### 2.4 现场使用前置条件

- 作业人员已登录 APP，服务端可达；
- 主桶、从桶已绑定到当前账号/单位，且绑定码有效；
- 所有参演设备在线、可用、未被其他事件/任务占用、未急停锁定；
- 所有参演锥桶按编队顺序置于同一起始线，朝向布设方向；
- 布设路线及转弯点无障碍物和人员；
- 现场安全条件已由作业人员/安全负责人确认；
- 扫码绑定需相机权限；地图定位需定位权限；部分系统版本还需局域网访问权限。

## 3. 术语与概念

| 术语 | 英文/字段 | 定义 |
|---|---|---|
| 布设事件 | Deployment Event / `deployment` | 一次多锥桶协同布设作业的完整会话 |
| 主桶 | master / `master_cone` | 编队首设备，先启动，负责按链路触发从桶 |
| 从桶 k | slave / `slave_cone`，`order=k` | 编队中第 k 只从桶，目标行程 `L − k·d` |
| 目标行程 | `targetM` | 设备从本次启动位置到计划位置应行驶的累计行程（米） |
| 当前累计行程 | `traveledM` | 设备自本次启动时刻起累计行驶的行程（米），以设备回报为准 |
| 启动间隔 | `d` / `intervalM` | 设备自身累计行程达到该值后，触发下一只桶或向主桶上报；单位米，不是秒 |
| 主桶目标行程 | `L` | 主桶从起始线到计划位置的累计行程（米） |
| 触发 | trigger | 主桶（或经服务端代发）向下一只从桶发送启动指令 |
| 上报 | report | 从桶自身累计行程达到 d 时，向主桶报告“已达到启动间隔” |
| 到达 | arrived | 设备当前累计行程达到其目标行程，由设备报告 |
| 现场核验 | verify | 现场人员逐只核对实际布设位置/处置方式并确认通过或异常 |
| 绑定 | bind | 把设备登记到账号/单位名下，进入可选设备列表 |
| 加入事件 | join / select | 作业人员在本次事件中选中某台已绑定设备，使其参与本次布设 |
| 占用 | occupied | 设备被某个进行中的事件或任务持有，不能加入其他事件 |
| 起始线 | start line | 所有参演锥桶启动前所在的共同起点线 |
| 转弯点 | `atM` | 沿路线从起点累计到转弯处的行程（米） |
| 带异常完成 | `completed_with_exception` | 事件完成，但过程中发生人工跳过等异常，需在记录中说明 |

> **三个必须区分清楚的概念**
>
> 1. **绑定 ≠ 加入事件**：绑定只是让设备进入可选列表；只有被本次事件选中，才参与本次布设。
> 2. **d 是距离，不是时间**：d 的单位是米，表示设备自身累计行程，不是“每隔多少秒启动下一只”。
> 3. **到达 ≠ 完成**：设备报告到达只代表行程到位，必须经现场人员逐只核验后事件才可完成。

## 4. 产品结构与流程

### 4.1 页面地图

```text
登录
└─ 作业类型选择
   └─ 锥桶协同布设
      ├─ 锥桶设备连接（主桶 / 从桶 / 编队 / 绑定 / 解绑）
      │  └─ 完成设备连接
      ├─ 锥桶作业主页（设备就绪 / 进行中事件 / 发布入口）
      │  ├─ 布设任务发布（事件信息 / L、d / 转弯 / 预览 / 预检 / 开始）
      │  └─ 布设执行（状态 / 地图 / 视频 / 异常 / 控制 / 手动干预 / 核验）
      └─ 记录
         └─ 锥桶页签（进行中事件 / 历史记录 / 详情）
```

### 4.2 导航规则

| 起点 | 动作 | 结果 |
|---|---|---|
| 登录成功 | 进入作业类型选择 | 可选择“锥桶协同布设” |
| 作业类型选择 | 选择锥桶协同布设 | 进入锥桶设备连接页，不要求先连接任何单设备 |
| 锥桶设备连接 | 完成设备连接 | 进入锥桶作业主页；连接页从返回栈移除 |
| 锥桶作业主页 | 发布协同布设任务 | 进入布设任务发布页 |
| 布设任务发布 | 发布并启动成功 | 进入布设执行页；发布页从返回栈移除 |
| 布设任务发布 | 修改设备 | 返回锥桶设备连接页，发布页从返回栈移除 |
| 布设执行 | 返回 | 退出执行页；事件仍在服务端继续执行，不会因返回而停止 |
| 底栏“作业” | 点击 | 回到当前作业类型的主页（锥桶模式为锥桶作业主页） |
| 底栏“记录” | 点击 | 记录页；锥桶页签展示布设事件 |
| 锥桶作业主页/记录 | 点击进行中事件卡片 | 进入执行页查看该事件 |
| 任意锥桶页 | 切换作业类型 | 回到作业类型选择；本次会话草稿保留 |
| 登录/登出/切换服务器 | 会话变化 | 清空旧会话的布设状态，避免旧数据覆盖新会话 |

### 4.3 端到端流程

1. **进入**：登录 → 作业类型选择 → 锥桶协同布设 → 锥桶设备连接。
2. **选设备**：选择 1 个主桶；从桶候选按“套装从桶”和“其他已绑定从桶”分组；勾选 0～5 个从桶并排序为从 1…从 N。
3. **绑定/解绑**：可扫码或输入编号绑定新设备；可解绑符合条件的设备；绑定成功后设备只进入可选列表，不自动加入事件。
4. **进入主页**：完成设备连接后，主页展示主桶、从桶顺序和设备就绪状态；有进行中事件时优先展示事件卡片。
5. **发布参数**：填写事件名、作业车道、备注；填写 L、d；可选添加最多 5 处 90° 转弯；查看目标行程和路线预览。
6. **预检确认**：核对自动条件，勾选“起始线/现场安全”和“编号/顺序”两项人工确认。
7. **发布并启动**：二次确认后创建事件并启动；服务端复验参数与占用，向主桶下发启动指令。
8. **逐级布设**：主桶先移动；主桶自身到 d 触发从 1；从 k 自身到 d 上报主桶，主桶触发从 k+1；设备可同时移动。
9. **执行监控**：APP 1Hz 轮询聚合状态，展示每只桶的启动、行程、到达、指令/上报结果、异常和下一步。
10. **到达与核验**：全部设备到达或人工跳过并完成处置后进入待核验；作业人员逐只核验。
11. **完成/终止**：全部核验通过后完成布设；有人工跳过则记录为“带异常完成”；异常无法恢复时终止事件。
12. **记录**：服务端固化事件记录；APP 记录页可查看列表和详情。

### 4.4 角色职责（RACI 简表）

| 事项 | APP | 服务端 | 主桶 | 从桶 |
|---|---|---|---|---|
| 设备选择/绑定 | 发起与展示 | 校验归属、返回候选 | — | — |
| 参数 L/d 校验 | 即时校验、阻止下一步 | 启动前复验、拒绝非法值 | — | — |
| 设备占用 | 展示冲突 | 原子占用/释放 | — | — |
| 链路编排 | 只展示 | 记录步骤、判超时、转指令 | 触发下一桶 | 上报、移动 |
| 行程/到达 | 展示 | 聚合、检测异常 | 上报自身 | 上报自身 |
| 暂停/终止 | 发起 | 下发停止、冻结链路 | 停止 | 停止 |
| 人工跳过 | 发起、现场确认与二次确认 | 校验、标记、触发下一只 | — | — |
| 现场核验 | 逐只确认 | 记录 | — | — |
| 审计记录 | 查询展示 | 权威存储 | 设备日志（可选） | 设备日志（可选） |

### 4.5 核心交互原则

1. **服务端是链路权威**：APP 不自行推算触发关系，不根据本地计时/插值推断设备状态。
2. **设备是行程权威**：累计行程、是否到达、是否已过 d，以设备回报/服务端聚合为准。
3. **异常必须显性**：任何异常都要展示原因、涉及设备和可执行动作，不静默忽略。
4. **不自动跳过、不自动重发运动指令**：只能由作业人员显式操作，并经过确认。
5. **危险动作二次确认**：暂停、继续、终止、重试、人工跳过、开始布设均需确认。
6. **颜色不是唯一信息载体**：状态必须同时有文字/图标，保证可读性。

7. 次操作：“刷新设备列表”。
8. 弹窗：绑定设备、解绑确认、错误提示、成功提示。

#### 5.2.8 可用性与占用规则

**可选设备条件（APP 软校验）**

```text
可选 = 设备类型已知
     ∧ 在线
     ∧ 可用
     ∧ 未被事件占用
     ∧ 无进行中任务
     ∧ 未急停锁定
```

**不可选原因展示优先级**

1. 设备类型未知（不是锥桶设备）；
2. 急停锁定中；
3. 已被事件占用（展示占用事件编号/名称）；
4. 正在执行任务；
5. 设备离线；
6. 设备不可用。

| 编号 | 需求 | 优先级 | 说明 |
|---|---|---|---|
| FR-2.31 | 被其他进行中事件占用的设备必须置灰并展示占用事件信息 | P0 | 不能加入本次布设 |
| FR-2.32 | 正在执行单设备任务的设备必须置灰并展示“正在执行任务” | P0 | 单设备任务与布设事件共享占用域 |
| FR-2.33 | 选择阶段的可用性只是软校验；启动时服务端必须再次原子校验并占用 | P0 | 防止选择后被抢占 |
| FR-2.34 | 启动时若设备被抢占/离线/急停/有任务，服务端必须拒绝并返回冲突设备清单，不得部分启动 | P0 | APP 展示冲突原因 |
| FR-2.35 | 事件进入完成/终止/失败终态后才释放占用 | P0 | 释放前需确认设备已停止或已现场处置 |
| FR-2.36 | 人工跳过的设备仍保持占用，直到事件终态并完成处置核验 | P0 | 不得因跳过提前释放 |

#### 5.2.9 完成设备连接校验

点击“完成设备连接”时，必须通过以下校验；任一不通过则展示错误并留在本页：

| 校验项 | 错误示例 |
|---|---|
| 已选择主桶 | 请选择主桶 |
| 从桶数量 0～5 | 从桶数量不能超过 5 |
| 从桶顺序连续唯一 1…N | 从桶顺序必须为连续的 1…N |
| 从桶不重复 | 从桶不能重复 |
| 主桶不能同时作为从桶 | 主桶不能同时作为从桶 |
| 主桶 `device_type=master_cone` | 所选主桶 device_type 必须为 master_cone |
| 从桶 `device_type=slave_cone` | 所选从桶中存在 device_type 不为 slave_cone 的设备 |
| 主桶/从桶具备 `binding_code` | 主桶 xxx 缺少 binding_code，请重新绑定 |
| 已选设备均可用 | 从桶 xxx：设备离线 / 已被事件占用 / 正在执行任务 / 急停锁定中 |

**交互行为**

- 有主桶时“完成设备连接”按钮即可点击；
- 点击后统一校验，错误以弹窗/错误列表展示，不跳转；
- 校验通过后进入锥桶作业主页；
- 设备列表刷新失败时展示错误，不展示假数据。

#### 5.2.10 空态与异常文案

| 场景 | 文案/操作 |
|---|---|
| 暂无可用主桶 | “暂无可用主桶，请先绑定。” + 绑定按钮 |
| 未选主桶时查看从桶 | “请先选择主桶。” |
| 主桶无套装且无从桶 | “暂无可用从桶，请先绑定。” + 绑定按钮 |
| 所有从桶被占用 | 逐行展示占用原因；可等待释放、改选其他从桶或绑定新设备 |
| 已有进行中事件 | 顶部展示事件卡片；提示“已有进行中事件，请先完成或终止。” |
| 设备列表加载失败 | 错误弹窗展示原因；可点击“刷新设备列表”重试 |
| 绑定失败 | 弹窗展示服务端原因；不清空已输入内容（便于修正） |
| 解绑失败 | 弹窗展示服务端原因；设备仍在列表中 |

#### 5.2.11 验收要点

- 只选主桶、不选从桶也可完成连接，主页显示“从桶：无（仅主桶执行）”；
- 选择主桶后自动出现套装/其他从桶分组；更换主桶清空已选从桶；
- 从桶最多选 5 只，取消后顺序自动重排；
- 绑定成功后设备出现在列表但未被自动勾选；
- 被占用/任务中/离线/急停设备无法选中，且有明确原因；
- 缺少绑定码时无法进入发布页；
- 进行中事件存在时，新事件创建被阻止并可跳转执行页。

#### 5.4.1 页面目标

#### 5.4.2 页面结构

1. 标题：“布设任务发布”，副标题“参数与预检”。

7. “自动条件”卡片：参数合法、无其他进行中事件、主桶已选择、从桶数量 0～5。

9. 安全提示横幅：“系统不会自动跳过或重发指令；请以现场安全验收为准。”
10. “开始前请修正”错误列表（如有）。
11. 主操作：“发布并开始协同布设”（忙碌时“正在启动…”）。

#### 5.4.6 布设预览

必须展示：

1. **目标行程列表**：
   - 主桶：`L`；
   - 从 k：`L − k × d`，k=1…N；
   - 保留 1 位小数；
   - 目标 ≤ 0.001 m 时显示“0.0 m · 无需移动”。
2. **路线摘要**（有转弯时）：
   - 起点 → 第 1 转弯点直行距离；
   - 每处转弯方向和角度；
   - 最后一个转弯点到 L 的直行距离；
   - 首个转弯点之前的桶数量提示。
3. **启动链路说明**：
   - “主桶到 d 启动从 1；从 k 到 d 上报后启动从 k+1。”
   - “d 是启动间隔，不是最终位置。”
4. **安全说明**：
   - 行程反馈只用于逐级启动与进度展示，不代表精确间距，也不等于现场安全验收。

#### 5.4.7 自动条件

| 条件 | 判定 | 不满足时 |
|---|---|---|
| 参数合法 | 事件信息 + 设备 + 参数 + 转弯校验全部通过 | 展示具体错误，禁用开始 |
| 无其他进行中事件 | `activeEvent == null` | 展示事件编号，禁用开始 |
| 主桶已选择 | `master != null` | 提示先完成设备连接 |
| 从桶数量 0～5 | `0 ≤ N ≤ 5` | 提示数量超限 |

> 选择阶段的在线/空闲/未被占用是软校验；最终以服务端启动时的原子校验为准。

| 复选框 | 文案 |

#### 5.4.10 错误与兼容处理

| 场景 | APP 行为 |
|---|---|
| L/d 非法 | 输入框标红 + 错误列表；禁用开始 |
| 转弯点非法 | 对应行标红 + 错误列表；禁用开始 |
| 无进行中事件检查失败 | 不阻塞页面；创建/启动时服务端再次校验 |
| 已有进行中事件 | 展示事件编号；禁用开始；可跳转执行页 |
| 设备被占用/离线/急停 | 服务端拒绝启动，展示冲突设备清单；APP 不高亮部分启动 |
| 缺少 binding_code | 创建前拦截并提示重新绑定 |
| 服务端不支持转弯 | 回显校验失败，自动取消创建，提示升级服务端 |
| 服务端回显 `turns` 结构非法 | 按不支持转弯处理，取消创建 |
| 网络超时/失败 | 展示错误；不自动重试创建/启动 |

#### 5.4.11 验收要点

- L=60、d=10、N=3 时预览为 60/50/40/30；
- L=30、d=10、N=3 时从 3 目标为 0，显示“0.0 m · 无需移动”；
- L<N×d 时开始按钮禁用并展示具体算式；
- N=0 时不显示 d 输入，仍可发布并仅主桶执行；
- 添加 5 处转弯后“添加转弯”禁用；第 6 处无法添加；
- 转弯点 ≥ L 或非递增时报错；
- 单转弯请求使用 `turn`，多转弯使用 `turns[]`；
- 旧服务端不回显转弯时，事件被取消并提示升级服务端；
- 未完成两项人工确认时无法开始。

### 5.5 布设执行页

#### 5.5.1 页面目标

以服务端聚合状态为准，实时展示多设备布设进展，支持暂停/继续、重试、受控人工跳过、单桶手动干预、现场核验和终止。

#### 5.5.2 页面结构与刷新机制

4. 主/从桶实时位置地图。
5. 主桶实时视频（非终态时）。
6. 异常卡片（如有）。
7. “下一步”卡片（服务端 `nextExpected`）。
8. 设备状态卡片列表（主桶在前，从桶按顺序）。
9. 次级处置按钮：重试当前步骤、人工跳过（仅异常阻断的从桶）。
10. 核验提示（待核验/核验异常时）。

#### 5.5.3 事件概览与状态

- 事件状态：准备中、启动中、执行中、已暂停、待现场核验、核验异常、已完成、已终止、失败；

- 有跳过时展示“跳过 N”；
- 事件 ID 便于现场沟通和问题定位。

#### 5.5.6 异常与下一步

**异常卡片**

- 一旦服务端返回 `anomalies[]`，必须在首屏显性展示；
- 每行展示涉及设备编号、异常文案、异常码；
- 固定提示：“请先暂停并现场处置；仅在异常阻断时可人工跳过。”

**下一步卡片**

- 根据 `nextExpected.type` 展示：
  - `trigger`：主桶到 X m → 触发从 1（或指定设备）；
  - `report`：从 k 到 X m 后上报 → 从 k+1；
  - 其他：等待指定设备。
- 固定说明：“按设备自身行程达到 d 触发，不是主桶累计 2d。”

#### 5.5.7 设备状态卡片

每只桶一张卡，主桶在前，从桶按 `order` 升序。必须展示：

| 字段 | 展示规则 |
|---|---|
| 角色 | “主桶”/“从 k” |
| 名称/编号 | 名称优先，编号辅助 |
| 连接状态 | 在线显示 phase；离线显示“离线” |
| 目标行程 | `targetM`，1 位小数 |
| 当前累计行程 | `traveledM`，1 位小数 |
| 无需移动 | 目标 ≤ 0.001 m 时显示“无需移动” |
| 进度 | `traveledM/targetM`，限制 0～100%；目标 0 不除零 |
| 已过启动间隔 d | 是/否 |
| 已到达 | 是/否 |
| 人工跳过 | 处置方式，或“待处置” |
| 启动指令 | 状态 + commandId |
| 上报结果 | 主桶显示“—（主桶）”；从桶显示状态 |
| 触发结果 | 主桶有 trigger 时显示 |
| 核验结果 | 已核验时显示通过/异常 + 备注 |
| 异常 | 异常文案 + 异常码 |
| 现场核验按钮 | 待核验/核验异常且该设备未核验时显示 |

**展示规则**

- 离线设备必须同时显示最后已知状态和“离线”，不得伪装实时；
- 不得把“指令已发送”展示为“已启动”；
- 不得把“已移动 d”展示为“已到达”；
- 状态颜色不作为唯一信息载体，必须配合文字；
- 人工跳过设备不得显示为“已到达”。

#### 5.5.8 底部操作栏

| 事件状态 | 主操作 | 次操作 |
|---|---|---|
| 执行中（RUNNING） | 暂停全部 | 终止事件 |
| 已暂停（PAUSED） | 继续布设 | 终止事件 |
| 待现场核验（PENDING_VERIFY）/核验异常（VERIFY_FAILED） | 完成布设（全部核验通过才可用） | 终止事件 |
| 启动中（STARTING） | 刷新状态 | 终止事件 |
| 终态（已完成/已终止/失败） | 刷新记录 | — |

**暂停全部**

- 二次确认：“将停止全部锥桶并冻结启动链路。”
- 暂停后所有设备停止；链路冻结，不再发新的启动指令；
- 暂停/停止未确认的设备必须展示“停止未确认”。

**继续布设**

- 二次确认：“全部锥桶将恢复自动移动，请确认现场安全。”
- 先停止手动点动，再恢复自动链路；
- 不得重新触发已完成的步骤。

**终止事件**

- 二次确认：“将停止全部锥桶并结束事件，不会标记为完成。”
- 终止后不再推进链路；离线设备标注“需现场处置”；
- 不自动视为完成。

#### 5.5.9 单桶手动干预

**入口**

- 执行中或已暂停时展示“单桶手动干预”大按钮；
- 执行中点击 → 二次确认“先暂停全部锥桶，再点动选中的一只；完成后需手动继续布设。”；
- 确认后调用暂停；等待轮询确认 PAUSED 后才允许点动；
- 已暂停时点击 → 直接打开手动干预框。

**对话框内容**

1. 设备选择下拉：主桶/从 k、编号、当前 phase、已行进/目标、是否手动中；
2. 选中设备摘要：目标行程、已行进、朝向；
3. 遥控方向盘：前进、后退、左转、右转、停止；
4. 状态提示：正在暂停/等待暂停/设备离线/已跳过/已到位/状态不可点动/目标已达成/按住点动；
5. 说明：“关闭后保持暂停，需手动继续布设。”
6. 按钮：“继续布设”“关闭（保持暂停）”。

**规则**

| 编号 | 需求 | 优先级 | 说明 |
|---|---|---|---|
| FR-5.21 | 仅事件处于 PAUSED 时允许点动 | P0 | RUNNING 必须先暂停 |
| FR-5.22 | 默认选择主桶；主桶不可点动时选择第一只可点动的桶 | P1 | 减少操作步骤 |
| FR-5.23 | 可点动设备条件：在线、phase=STOPPED、未到达、未跳过、未达目标 | P0 | 服务端同时校验急停等 |
| FR-5.24 | 同一事件同一时间只允许一只桶手动动作 | P0 | 单桶互斥 |
| FR-5.25 | 按住方向键持续点动，松手停车；另提供“停止”按钮 | P0 | 防止持续失控 |
| FR-5.26 | 保活周期 300 ms；服务端 800 ms 未收到保活应停止该桶 | P0 | 断网/APP 卡死时设备自动停 |
| FR-5.27 | 手动移动计入该桶累计行程，并更新地图估算位置 | P0 | 与自动行程统一 |
| FR-5.28 | 暂停期间手动移动不得触发后继设备 | P0 | 链路保持冻结 |
| FR-5.29 | 关闭手动框后事件保持暂停，不自动继续 | P0 | 必须显式“继续布设” |
| FR-5.30 | 离开执行页/切后台时停止点动并关闭手动框，事件保持暂停 | P0 | 安全优先 |
| FR-5.31 | 轮询发现事件离开 PAUSED 或进入终态时，自动关闭手动框并停止点动 | P0 | 防止状态漂移 |
| FR-5.32 | 手动操作被拒绝时展示服务端原因；网络超时类错误不重复弹窗 | P1 | 避免刷屏 |

**方向语义**

- 前进/后退：沿当前朝向移动；
- 左转/右转：改变朝向（v1 固定 90° 语义由设备/服务端定义，APP 只发送方向）；
- 手动移动后地图位置和朝向以服务端聚合状态为准。

#### 5.5.10 重试当前步骤

| 编号 | 需求 | 优先级 | 说明 |
|---|---|---|---|
| FR-5.33 | 仅当存在“启动指令超时/被拒绝/启动失败/上报丢失”的设备时展示“重试当前步骤” | P0 | 不满足时不显示 |
| FR-5.34 | 重试前二次确认，说明“复用同一指令重试；已执行设备不会二次移动” | P0 | 不得自动重试 |
| FR-5.35 | 启动重试复用原 `commandId`；上报重试携带 `reportId` | P0 | 服务端/设备幂等 |
| FR-5.36 | 重试成功后刷新聚合状态；失败展示原因 | P0 | 结果未知时不得显示成功 |

#### 5.5.11 受控人工跳过

**显示条件**

- 事件处于 RUNNING；
- 存在“当前阻断”的从桶（启动失败/超时/被拒绝/上报丢失/离线且前序已就绪或自身已启动）；
- 主桶不显示“人工跳过”。

**跳过后台规则**

- 仅异常阻断时可用；仅从桶；不得预跳过尚未轮到的从桶；
- 必须由作业人员显式发起；
- 对话框必须包含三项确认：
  1. 已确认该设备已停止或已移出运动路径；
  2. 已确认下一只从桶的启动路径安全；
  3. 已了解将记录为“带异常完成”。
- 必须选择处置方式：人工摆放到位 / 移出路线 / 不参与本次布设；
- 必须填写跳过原因（≤100 字），备注可选（≤100 字）；
- 三项确认 + 原因必填后才可提交。

**服务端行为**

1. 先向被跳过设备下发停止指令；离线时记录“停止未确认/需现场处置”；
2. 标记该设备为 `skipped_manual`，不记为到达；
3. 若存在下一只从桶，校验其在线/可用后下发启动指令；
4. 若下一只不可用，整次跳过失败，不得只标记不启动；
5. 日志记录 `cause=manual_skip`、操作人、原因、处置方式；
6. 事件完成结果必须为 `completed_with_exception`；
7. 被跳过设备仍保持占用，直到事件终态并完成处置核验。

| 编号 | 需求 | 优先级 | 说明 |
|---|---|---|---|
| FR-5.37 | 人工跳过按钮仅在 RUNNING 且存在阻断从桶时出现 | P0 | 主桶不显示 |
| FR-5.38 | 跳过对话框三项确认、处置方式、原因缺一不可 | P0 | 确认按钮禁用直到满足 |
| FR-5.39 | 跳过成功后刷新状态，并明确提示“事件将记录为带异常完成” | P0 | 不伪装正常完成 |
| FR-5.40 | 跳过失败展示服务端原因，不修改本地状态 | P0 | 如下一只不可用 |
| FR-5.41 | 被跳过设备必须接受现场核验（核验处置方式） | P0 | 未处置不得完成 |

#### 5.5.12 现场核验与完成

**进入条件**

- 全部设备到达，或人工跳过并完成处置后，服务端将事件置为 `PENDING_VERIFY`；
- 任一设备未到达/离线/失败/超程，不得进入待核验，必须先恢复、跳过处置或终止。

**逐只核验**

| 编号 | 需求 | 优先级 | 说明 |
|---|---|---|---|
| FR-5.42 | 待核验/核验异常时，每只未核验设备展示“现场核验”按钮 | P0 | 主桶和从桶都要核验 |
| FR-5.43 | 核验对话框支持“核验通过”/“发现异常”，并可填写备注 | P0 | 备注上限 120 字（UI） |
| FR-5.44 | 默认备注：正常设备“位置/朝向/间距/灯光正常”；跳过设备“已核对跳过处置方式” | P1 | 减少输入成本 |
| FR-5.45 | 核验通过只代表该只桶现场位置/处置被确认，不得自动推断其他桶 | P0 | 逐只确认 |
| FR-5.46 | 全部设备核验通过后，“完成布设”按钮才可用 | P0 | 包括无需移动和人工跳过设备 |
| FR-5.47 | 任一设备核验异常时，事件进入“核验异常”；可重新核验或终止 | P0 | 修正后重新核验 |
| FR-5.48 | 核验动作记录操作人、时间、结果、备注 | P0 | 服务端权威 |
| FR-5.49 | 提示“请核对实际位置、朝向、间距、灯光与现场安全条件”，不得只核对 APP 数字 | P0 | 现场安全优先 |
| FR-5.50 | 人工跳过设备核验的是处置方式，不是到达 | P0 | 未处置不得完成 |

**完成**

- 完成操作必须由作业人员显式触发；
- 无人工跳过：`result=completed`；
- 有人工跳过：`result=completed_with_exception`，记录被跳过设备、原因、操作人、处置方式；
- 完成后释放设备占用；
- 完成后不得再修改核验结果（修正走异常/审计流程，后续规划）。

#### 5.5.13 验收要点

- 执行页 1Hz 刷新，切后台/离开后停止轮询；
- 每只桶展示目标/累计行程、启动指令、上报结果、到达/核验状态；
- 离线设备显示“离线”，不伪装实时；
- 异常出现时首屏可见，展示异常码和处置提示；
- 执行中可暂停/终止；暂停后可继续/终止；
- 待核验时逐只核验，全部通过后“完成布设”可用；
- 有人工跳过时完成结果显示“带异常完成”；
- 手动干预只在 PAUSED 可用，关闭后保持暂停；
- 重试复用原指令，不产生二次移动；
- 主桶不出现人工跳过按钮。

## 6. 核心业务规则

### 6.1 参数定义与校验

#### 6.1.1 公式

```text
target(master) = L
target(slave k) = L − k × d        (k = 1..N)
```

#### 6.1.2 校验规则（APP 与服务端必须一致）

```text
0 ≤ N ≤ 5
d > 0
L > 0
L ≥ N × d
L ≤ 200 m
d ≤ 50 m
精度 0.1 m
```

#### 6.1.3 参数约束表

| 参数 | 范围 | 精度 | 说明 |
|---|---|---|---|
| N | 0～5 | 整数 | N=0 表示仅主桶执行 |
| L | 1.0～200.0 m | 0.1 m | 主桶目标行程 |
| d | >0 且 ≤50.0 m | 0.1 m | 相邻设备启动间隔；N=0 时不参与控制 |
| 事件名 | ≤30 字 | — | 留空使用默认名 |
| 备注 | ≤100 字 | — | 可选 |
| 车道 | 1～8 | 整数 | 必填 |
| 转弯数 | 0～5 | 整数 | 每处固定 90° |
| 转弯点 atM | >0 且 <L，严格递增 | 0.1 m | 从起点累计 |

#### 6.1.4 边界情况

| 情况 | 规则 |
|---|---|
| `L = N·d` | 允许；最后一只从桶目标为 0，按“无需移动”处理，仍需核验 |
| 最后一只从桶目标 `0 < target < d` | 允许；只移动到目标，无后继，不要求达到 d 上报 |
| 非最后从桶目标 | 数学上必 ≥ d，必须能上报并触发下一只 |
| 目标为 0 | 显示“0.0 m · 无需移动”，进度不除零 |
| 精度超过 0.1 m | 拒绝 |
| 负数/非数字 | 拒绝 |

### 6.2 逐级启动链路（核心）

#### 6.2.1 链路规则

| 步骤 | 触发条件 | 动作 | 目标 |
|---|---|---|---|
| S0 | 作业人员确认开始 | 服务端向主桶下发启动 | 主桶按 L 移动 |
| T1 | 主桶自身行程 ≥ d | 主桶触发从 1 | 从 1 按 L−d 移动 |
| R1 | 从 1 自身行程 ≥ d | 从 1 上报主桶 | — |
| T2 | 主桶收到 R1 | 主桶触发从 2 | 从 2 按 L−2d 移动 |
| R2 | 从 2 自身行程 ≥ d | 从 2 上报主桶 | — |
| T3 | 主桶收到 R2 | 主桶触发从 3 | 从 3 按 L−3d 移动 |
| … | … | … | … |
| TN | 主桶收到 R(N−1) | 主桶触发从 N | 从 N 按 L−N·d 移动 |
| RN | 从 N 自身行程 ≥ d（若 target ≥ d） | 上报（信息性） | 无后继 |
| A_k | 设备自身行程 ≥ target(k) | 设备报告到达并停车 | — |
| MS_k | 作业人员人工跳过从 k（仅异常阻断时） | 触发从 k+1（若有） | 从 k 标记 `skipped_manual` |

#### 6.2.2 核心不变量（必须写入代码与测试）

> **INV-1**：`target(master) = L`，`target(slave k) = L − k·d`。
>
> **INV-2**：触发从 k+1 的唯一原因，是收到从 k 的“已达到启动间隔 d”上报（或经服务端幂等重投的同一上报），**不是**主桶累计行程达到 `(k+1)·d`。
>
> **INV-3**：从 k 的上报条件是“从 k 自身累计行程 ≥ d”，不是“从 k 已到达最终目标”。
>
> **INV-4**：设备到达条件是“自身累计行程 ≥ 自身目标行程”，与是否上报无关。
>
> **INV-5**：设备通过 d 后继续移动；多只桶可同时处于移动状态。
>
> **INV-6**：任何异常都不得**自动**跳过某只桶去启动后续设备；仅允许作业人员在链路被异常阻断时，经现场安全确认与二次确认后**人工跳过从桶**（主桶不可跳过），并全程留痕。
>
> **INV-7**：启动/运动指令不得自动重发；上报可以幂等重发。
>
> **INV-8**：从桶不得直接触发从桶；触发者只能是主桶（或服务端明确代主桶下发，并在日志中标注 `from=master, relay=true`）。
>
> **INV-9**：人工跳过不属于正常链路；被跳过设备状态为 `skipped_manual`，不计为到达；事件完成结果必须为 `completed_with_exception`。
>
> **INV-10**：暂停期间不得触发任何后继设备；继续后只恢复尚未完成的步骤，不得重复触发已完成步骤。

#### 6.2.3 链路时序（服务端中继）

```text
APP           服务端                主桶               从1              从2
 │  创建/开始   │                    │                 │                │
 │─────────────→│ deploy_start(L,d)  │                 │                │
 │              │───────────────────→│                 │                │
 │              │←──── start_ack ────│                 │                │
 │              │                    │── 自身行程≥d ──→│                │
 │              │←─ trigger_request ─│                 │                │
 │              │──── deploy_start ───────────────────→│                │
 │              │←────────────── start_ack ────────────│                │
 │              │                    │←─ 行程≥d 上报 ──│                │
 │              │←─ interval_reached（地址=主桶）───────│                │
 │              │──── deploy_start（from=主桶）───────────────────────→│
 │              │                    │                 │                │
 │              │   （从1、从2继续各自向目标移动，不停车等待）              │
```

> 关键：服务端给从 2 下发启动指令的**原因**必须是“收到从 1 的上报”，而不是“主桶行程达到 2d”。服务端日志必须记录 `causeReportId`。

#### 6.2.4 示例（必须按此验收）

设 `L=60 m`、`d=10 m`、`N=3`：

| 设备 | 目标行程 | 触发/上报条件 |
|---|---|---|
| 主桶 | 60 m | 自身到 10 m → 触发从 1 |
| 从 1 | 50 m | 自身到 10 m → 上报主桶 → 主桶触发从 2 |
| 从 2 | 40 m | 自身到 10 m → 上报主桶 → 主桶触发从 3 |
| 从 3 | 30 m | 自身到 10 m → 上报（无后继） |

**反例（必须判为错误）**

- 主桶到 20 m 时触发从 2（错误：应由从 1 的上报到 10 m 触发）；
- 从 1 到 10 m 时标记“从 1 已到达”（错误：从 1 还要继续到 50 m）；
- 从 1 到 10 m 后停车等待（错误：应继续移动）；
- 从 1 上报丢失后自动启动从 2（错误：应显示异常并阻断）。

### 6.3 路线转弯规则

| 规则 | 说明 |
|---|---|
| 默认直行 | 不添加转弯时，路线为从起点沿当前朝向的直线 |
| 固定角度 | 每处转弯固定 90°，方向左/右 |
| 转弯点定义 | `atM` 为沿路线从起点累计的行程，不是地图坐标 |
| 顺序 | 多个转弯点必须严格递增 |
| 范围 | 每个 `atM` 必须大于 0 且小于 L |
| 目标落点 | 设备目标行程可能落在转弯点之前；此时该设备不会经过该转弯 |
| 链路不受影响 | 逐级启动仍按设备自身累计行程 d 判断，与是否过弯无关 |
| 兼容 | 0 处不发字段；1 处发 `turn`；≥2 处发 `turns[]`；APP 校验服务端回显 |
| 静默降级禁止 | 服务端不回显转弯时，APP 必须取消创建，不得按直行继续 |

### 6.4 指令确认、幂等与去重

| 对象 | 键 | 行为 |
|---|---|---|
| 创建事件 | `clientRequestId` | 重复创建返回同一事件 |
| 启动/暂停/继续/终止 | `commandId` | 重复请求返回当前结果，不重复执行 |
| 设备启动指令 | `commandId` | 设备去重；重复返回 `duplicate=true` 与当前状态 |
| 人工跳过 | `skipRequestId` | 重复跳过返回当前处置状态；不得重复触发下一只 |
| 间隔上报 | `reportId = deploymentId:device_code:interval:seq` | 可幂等重发；接收方去重；只触发一次 |
| 到达上报 | `reportId = deploymentId:device_code:arrived:1` | 去重 |
| 核验 | `(deploymentId, device_code, verifyRevision)` | 同一结果幂等；变更记录审计 |
| 完成 | `deploymentId` | 重复完成返回最终状态 |

**边沿触发要求**

- 设备必须在本地对 `traveled ≥ d` 做**上升沿**检测；跨过阈值只产生一次 `interval_reached`；
- 轮询多次看到 `traveled > d` 不得重复上报/触发；
- 主桶对每个 `(deploymentId, predecessorOrder)` 只处理一次有效上报；
- 服务端对每个 `(deploymentId, stepSeq)` 只允许一条有效启动指令。

### 6.5 事件状态机

```text
READY ──start──→ STARTING ──master ack──→ RUNNING
                    │                       │
                    │ 明确拒绝/不可恢复      ├──pause──→ PAUSED ──resume──→ RUNNING
                    ↓                       │
                  FAILED                    ├──all arrived / skipped disposed──→ PENDING_VERIFY
                                            │                       │
                                            │                       ├──all verify pass──→ COMPLETED
                                            │                       └──verify fail──→ VERIFY_FAILED
                                            │                                              │
                                            │                                              ├──re-verify──→ PENDING_VERIFY
                                            │                                              └──abort──→ ABORTED
                                            └──abort──→ ABORTED
```

| 状态 | 中文 | 允许动作 | 说明 |
|---|---|---|---|
| `READY` | 准备中 | start, cancel | 已创建未启动；READY TTL 30 分钟，超时自动取消 |
| `STARTING` | 启动中 | refresh, abort | 已占用设备；主桶启动指令在途；结果未知时先核对状态，不自动重发 |
| `RUNNING` | 执行中 | pause, abort, retry blocked step, manual skip（仅从桶/异常阻断） | 链路推进中 |
| `PAUSED` | 已暂停 | resume, abort, manual jog | 所有设备已停止/停止中；链路冻结 |
| `PENDING_VERIFY` | 待现场核验 | verify, complete, abort | 所有设备已到达，或人工跳过并完成处置 |
| `VERIFY_FAILED` | 核验异常 | re-verify, abort | 有核验异常 |
| `COMPLETED` | 已完成 | — | 终态；`completed` 或 `completed_with_exception`；释放占用 |
| `ABORTED` | 已终止 | — | 终态；释放占用 |
| `FAILED` | 失败 | — | 终态；释放占用；需现场确认 |

> **异常不改变事件顶层状态**：设备离线、上报丢失、指令超时等以 `anomalies[]` 呈现并阻断链路；只有设备/服务端明确拒绝且不可恢复时才进入 `FAILED`。
>
> **启动超时/结果未知不是 FAILED**：`STARTING` 下主桶启动指令超时，事件保持 `STARTING`，增加 `start_timeout` 异常，等待状态核对、人工重试或终止。

### 6.6 设备状态机

```text
not_started ──start──→ start_sent ──ack──→ start_acked ──move──→ moving
                                                    │                  │
                                                    │ target=0         ├──traveled≥target──→ arrived
                                                    ↓                  │
                                                 no_move               └──pause/stop──→ stopped ──resume──→ moving
start_sent/start_acked/moving ──明确拒绝/不可恢复错误──→ failed
start_sent/start_acked/moving ──人工跳过（仅异常阻断，服务端标记）──→ skipped_manual
```

| 状态 | 中文 | 规则 |
|---|---|---|
| `not_started` | 待启动 | 未收到启动指令，不得移动 |
| `start_sent` | 启动指令已发送 | 等待设备 ack；超时显示“结果未知” |
| `start_acked` | 已接收 | 设备已确认，等待移动 |
| `moving` | 移动中 | 按目标行程移动；过 d 后继续移动 |
| `stopped` | 已暂停/已停止 | 暂停或停止；可手动点动（条件满足时） |
| `arrived` | 已到达（待核验） | 行程达到目标；不再接受运动指令 |
| `no_move` | 无需移动 | 目标为 0；视为已触发、已到达，仍需核验 |
| `skipped_manual` | 人工跳过（待处置） | 不计到达；必须记录处置方式并核验 |
| `failed` | 启动失败/异常 | 不可自动恢复；需现场处置/终止 |

- `online` 是独立连接标志，不是 phase；离线时保留最后 phase 并显示“离线”；
- `arrived` 后不再接受运动指令；核验单独记录；
- `no_move` 视为已触发、已到达，但仍需核验；
- `skipped_manual` 主桶不得进入；
- 启动指令超时属于“结果未知”，不是 `failed`。

### 6.7 占用与互斥

```text
选择（软校验，不占用）
   ↓ 点击开始
服务端事务性占用（STARTING）
   ↓
RUNNING / PAUSED / PENDING_VERIFY / VERIFY_FAILED（持续占用）
   ↓ 完成/终止/失败
确认设备已停止或已现场处置
   ↓
释放占用
```

| 编号 | 规则 |
|---|---|
| BR-7.1 | 占用粒度为设备，不是套装；未选中的套装从桶不被占用 |
| BR-7.2 | 单设备任务与布设事件共享同一占用域 |
| BR-7.3 | 同一作业人员同一时间只允许一个非终态布设事件 |
| BR-7.4 | 服务端拒绝创建第二个非终态事件时，返回现有事件 ID，APP 提示并可跳转 |
| BR-7.5 | 启动时若设备被抢占/离线/急停/有任务，服务端拒绝并返回冲突清单，不得部分启动 |
| BR-7.6 | 事件进入终态后才释放占用；释放前需确认设备已停止或已现场处置 |
| BR-7.7 | 人工跳过的设备仍保持占用，直到事件终态并完成处置核验 |
| BR-7.8 | 服务端重启后必须恢复占用；不得把仍在运动/状态未知的设备释放给其他事件 |
| BR-7.9 | READY 事件超过 30 分钟未启动，服务端自动取消，避免阻塞新建 |
| BR-7.10 | 设备停止未确认/离线时，释放前标记“需现场处置”，不得静默释放 |

### 6.8 地图位置估算规则

- APP 不获取每只桶的 GPS；地图点位是**估算**；
- 锚点优先取事件开始时刻附近的手机定位；进行中事件要求定位点足够新，历史事件可放宽；
- 优先使用服务端 `pos {x,y}`（相对起始线，东/北，米）和 `headingDeg`；旧服务端无 `pos` 时，按 `traveledM` 沿正北投影回退；
- 轨迹按 1Hz 采样，过滤静止抖动，单桶轨迹限制长度；
- 颜色：蓝=主桶、橙=从桶、绿=到位、灰=跳过；
- 无锚点时不得显示点位，必须提示“无法估算”；
- 地图仅用于现场辅助，不得作为间距精确性、路径正确性或安全验收的依据。

### 6.9 异常、超时与安全红线

#### 6.9.1 异常清单

| 异常 | 判定 | 影响 | APP 展示 | 允许动作 |
|---|---|---|---|---|
| 设备启动前离线 | 在线检查失败 | 不能启动 | 设备高亮“离线” | 移除/等待/刷新/重新绑定 |
| 设备运行中离线 | 服务端超过 `T_DEVICE_OFFLINE` 未收到状态/事件 | 设备本地断链停车；链路可能阻断 | 红色横幅 + 设备卡“离线” | 暂停、现场处置、恢复后重试、终止 |
| 启动指令超时 | 发出后 `T_ACK` 内无 ack | 启动未确认 | “结果未知” | 查询状态、幂等重试、终止 |
| 启动指令被拒绝 | 设备/服务端 `accepted=false` | 链路阻断 | 原样展示原因 | 排除后重试、终止 |
| 上报丢失 | 行程已 ≥d，但 `T_REPORT` 内无有效上报 | 下一只不启动，链路阻断 | “上报丢失，后续设备不会自动启动” | 请求重报、刷新、现场处置、受控跳过、终止 |
| 上报超时/乱序 | 期望从 k 上报，收到其他/重复 | 链路阻断或忽略重复 | 异常详情 | 检查、重试、终止 |
| 到达超时 | 超过预计时间仍未到达 | 设备可能卡住 | “到达超时” | 暂停、现场处置、终止 |
| 超程 | 行程超过目标 + 容差 | 设备可能越过计划位置 | “超程” | 暂停/停止、现场处置、终止 |
| 设备故障/急停 | `fault` / `estopLocked` | 链路阻断 | 故障/急停 | 现场处置、恢复/终止 |
| 设备被占用冲突 | 启动时服务端 409 | 不能启动 | 冲突设备清单 | 移除/替换/终止 |
| APP 与服务端断开 | 聚合状态请求失败 | APP 非实时；服务端可能继续 | “手机与服务器断开” | 重连、刷新；紧急情况用设备急停 |
| 链路步骤结果未知 | 指令/上报超时 | 不能推进 | “结果未知” | 按安全流程重试、终止 |
| 链路被异常阻断 | 离线/上报丢失/启动失败/到达超时 | 后续设备无法正常启动 | 异常原因 + 可人工跳过（受控） | 人工跳过（仅从桶）、重试、暂停、终止 |

#### 6.9.2 超时阈值（建议，服务端可配置）

| 常量 | 采用值 | 说明 |
|---|---|---|
| `T_ACK` | 3 s | 启动指令等待 ack |
| `T_REPORT` | 3 s | 设备行程已 ≥d 后等待上报 |
| `T_DEVICE_OFFLINE` | 5 s | 服务端超过该时间未收到设备状态/事件 |
| `T_APP_STALE` | 3 s | APP 聚合状态过期，标注非实时 |
| `T_ARRIVAL` | `target / v_min + 30 s` | 到达监控阈值；`v_min` 建议 0.2 m/s |
| `T_PAUSE_ACK` | 3 s | 暂停/停止指令 ack |
| `T_SKIP_STOP_ACK` | 3 s | 人工跳过时向被跳过设备下发停止的 ack 等待 |
| `T_SESSION_IDLE` | 30 min | READY 未启动过期 |

> APP 只展示服务端返回的异常，不自行判定链路超时。

#### 6.9.3 安全红线（必须）

1. 不得自动跳过任何一只桶去启动后续设备；人工跳过是受控例外（仅异常阻断、仅从桶、现场确认 + 二次确认 + 留痕）。
2. 不得自动重发启动/运动指令；只能人工按安全流程重试。
3. 上报可以自动幂等重发，但不得触发两次。
4. 暂停必须停止所有正在移动的设备；暂停后不得再发新的启动指令。
5. 终止后不得再推进链路。
6. 任何“结果未知”不得展示为“成功”。
7. 设备离线时，APP 不得假设其已停止；必须提示现场核实。
8. 行程反馈不得用于宣称“间距精确”或“现场安全验收已完成”。
9. 人工跳过不得把事件伪装为正常完成；结果必须为“带异常完成”。
10. 主桶不可人工跳过；主桶异常只能暂停、现场处置或终止。

### 6.10 完成判定与记录固化

- 设备到达以自身累计行程 ≥ 目标行程为准（允许设备固件停车容差）；
- 目标为 0 的从桶被触发后标记“无需移动/已到达”；
- 所有设备报告到达，或人工跳过并完成处置后，事件进入“待核验”；
- 任一设备未到达、离线、失败或超程，不得进入“待核验”；
- “设备报告到达”不得自动等于“事件完成”；
- 人工跳过的设备不记为到达；其处置方式（人工摆放到位/移出路线/不参与本次布设）必须记录并核验；
- 完成操作必须由作业人员显式触发；完成后固化记录并释放占用；
- 有人工跳过时，结果必须为 `completed_with_exception`，不得伪装为正常完成。

| POST | `/deployments/{id}/complete` | 完成布设 | `deploymentId` |
| POST | `/deployments/{id}/manual/move` | 单桶点动 | `commandId` + `sessionId` + `seq` |
| POST | `/deployments/{id}/manual/stop` | 单桶停止 | `commandId` + `sessionId` + `seq` |
| GET | `/device/video/stream?device_code={code}&token={token}` | 主桶视频（UDP 传输） | — |

> 设备端上报/触发接口、服务端编排细节不在 APP 侧接口表中展开，参见后端接口设计文档与 `tools/mock-server/deployment.js`。

### 7.3 关键请求字段

**创建事件**

```json
{
  "clientRequestId": "uuid",
  "name": "锥桶协同布设",
  "lane": 2,
  "note": "",
  "master": {
    "device_code": "CONE-M-001",
    "device_type": "master_cone",
    "binding_code": "123456"
  },
  "slaves": [
    {
      "device_code": "CONE-S-001",
      "device_type": "slave_cone",
      "binding_code": "123456",
      "order": 1
    }
  ],
  "L": 60.0,
  "d": 10.0,
  "turn": { "dir": "left", "atM": 35.0 }
}
```

- 直行：不发送 `turn`/`turns`；
- 单转弯：发送兼容字段 `turn`；
- 2 处及以上：发送 `turns: [{ "dir": "left|right", "atM": 35.0 }, ...]`；
- N=0 时 `slaves` 为空数组，`d` 仍发送 1.0 占位（服务端契约要求 d>0）。

**启动事件**

```json
{
  "commandId": "uuid",
  "confirmed": true,
  "precheck": {
    "startLineConfirmed": true,
    "orderConfirmed": true,
    "safetyConfirmed": true
  }
}
```

**控制动作**

| 动作 | 关键字段 |
|---|---|
| pause | `commandId`, `reason` |
| resume | `commandId`, `confirmed=true` |
| abort | `commandId`, `reason` |
| retry | `requestId`, `type`（start_command/report）, `device_code`, `device_type`, `originalCommandId`（启动重试）, `reportId`（上报重试） |
| skip | `skipRequestId`, `device_code`, `device_type`, `reason`, `disposition`, `note`, `confirmations {deviceStoppedOrRemoved,nextPathSafe,understandException}` |
| verify | `device_code`, `device_type`, `result`（pass/fail）, `note` |
| complete | 无额外字段 |

**手动干预**

```json
{
  "commandId": "uuid",
  "sessionId": "uuid",
  "seq": 1,
  "device_code": "CONE-M-001",
  "device_type": "master_cone",
  "dir": "fwd"
}
```

- `dir`：`fwd` / `back` / `left` / `right`；
- 保活周期 300 ms；服务端 800 ms 看门狗；手动请求使用更短超时（连接 500 ms / 读取 700 ms）。

## 8. 非功能需求

### 8.1 性能与实时性

| 编号 | 需求 | 目标 |
|---|---|---|
| NFR-1 | 执行页状态轮询 | 页面可见时 1Hz；不可见/后台停止 |
| NFR-2 | 普通控制请求超时 | 连接 1.5 s，读取 3 s（当前实现） |
| NFR-3 | 手动点动请求超时 | 连接 500 ms，读取 700 ms；300 ms 保活；800 ms 看门狗 |
| NFR-4 | 页面首屏 | 设备列表/事件状态加载中展示骨架或加载提示，不阻塞其他操作 |
| NFR-5 | 地图与视频 | 地图/视频故障不得阻塞布设状态展示和控制 |
| NFR-6 | 长列表 | 记录列表使用懒加载，避免大列表卡顿 |

### 8.2 可靠性与一致性

| 编号 | 需求 |
|---|---|
| NFR-7 | 所有控制动作必须幂等；重复提交不得产生重复运动/重复触发 |
| NFR-8 | 服务端是事件状态、占用和链路步骤的唯一权威；APP 不做本地推测 |
| NFR-9 | 网络失败/超时展示可读错误，不自动重试运动指令 |
| NFR-10 | 服务端重启后恢复事件、占用和链路状态；APP 重新进入可继续查看 |
| NFR-11 | APP 切后台/断网不改变服务端继续编排的事实；恢复后以服务端状态为准 |
| NFR-12 | 设备停止未确认时不得静默释放占用；标记“需现场处置” |

### 8.3 安全

| 编号 | 需求 |
|---|---|
| NFR-13 | 所有危险动作二次确认，确认文案说明后果 |
| NFR-14 | 人工跳过仅异常阻断、仅从桶、三项确认 + 处置方式 + 原因 |
| NFR-15 | 主桶不可跳过、不可手动标记为跳过 |
| NFR-16 | 设备离线时提示现场核实，不得假设已停止 |
| NFR-17 | 行程数据不得用于宣称精确间距或安全验收完成 |
| NFR-18 | 绑定码、Token 等敏感信息不得在日志/UI 中明文展示（绑定码输入除外） |
| NFR-19 | 设备断链应本地停车；急停优先于所有远程指令 |

### 8.4 兼容性

| 编号 | 需求 |

## 9. 验收标准

| 编号 | 场景 | 前置条件 | 步骤 | 预期结果 |
|---|---|---|---|---|
| AC-01 | 独立入口 | 已登录，未连接任何单设备 | 作业类型选择 → 锥桶协同布设 | 进入锥桶设备连接页，不被单设备连接阻断 |
| AC-02 | 设备绑定 | 未绑定主桶/从桶 | 扫码或输入编号 + 绑定码绑定 | 绑定成功；设备进入候选列表但未自动勾选；失败展示原因 |
| AC-03 | 设备选择与排序 | 主桶、≥3 个从桶可用 | 选主桶，勾选 3 个从桶，上移/下移，移除 1 个 | N=2，顺序自动重排为从 1、从 2；预览同步更新 |
| AC-04 | 参数校验 | 已选主桶 + 3 从桶 | 输入 L=25、d=10 | 提示 L≥N×d（25<30），开始按钮禁用 |
| AC-05 | 仅主桶执行 | 已选主桶，N=0 | 填写 L=30，完成预检并开始 | d 输入隐藏；仅主桶按 L 移动；无逐级触发 |
| AC-06 | 标准链路 | L=60、d=10、N=3，设备在线 | 启动并观察 | 目标 60/50/40/30；主桶到 10 触发从 1；从 1 到 10 上报后触发从 2；不出现主桶 20 触发从 2 |
| AC-07 | 目标为 0 | L=30、d=10、N=3 | 启动并观察 | 从 3 目标 0，显示“无需移动”；不移动但需核验 |
| AC-08 | 路线转弯 | L=60、d=10、N=2，添加 2 处转弯 | 填写 atM 并发布 | 转弯点必须递增且 <L；服务端回显 `turns[]` 与输入一致 |
| AC-09 | 旧服务端转弯 | 服务端无 `turns` 回显 | 添加转弯并发布 | APP 取消创建并提示升级服务端，不按直行继续 |
| AC-10 | 设备占用冲突 | 目标从桶被其他事件占用 | 尝试选中/启动 | 选择页置灰并显示占用原因；启动时服务端拒绝并返回冲突清单，不部分启动 |
| AC-11 | 上报丢失阻断 | 从 1 到 d 后上报丢失 | 观察执行页 | 显示“上报丢失”，后续从桶不自动启动；可重试/受控跳过/终止 |
| AC-12 | 受控人工跳过 | 从 1 上报丢失且无法恢复 | 点击“人工跳过从 1”，完成三项确认、选处置方式、填原因 | 从 1 标记跳过、不计到达；从 2 启动；事件结果为带异常完成 |
| AC-13 | 启动指令超时重试 | 某从桶启动超时 | 点击“重试当前步骤”并确认 | 复用原 commandId；已执行设备不二次移动；状态刷新 |
| AC-14 | 暂停/继续 | 事件执行中 | 暂停全部 → 继续布设 | 全部设备停止，链路冻结；继续后恢复自动移动，不重复已触发步骤 |
| AC-15 | 单桶手动干预 | 事件执行中 | 点击“单桶手动干预” → 暂停并进入 → 选择主桶 → 按住前进 → 松手 → 关闭 | 仅主桶动作；300ms 保活；关闭后保持暂停；不自动继续 |
| AC-16 | 现场核验 | 事件进入待核验 | 逐只核验，全部通过后完成 | 每只桶记录结果；全部通过后“完成布设”可用；完成记录生成 |
| AC-17 | 核验异常 | 某只桶核验发现异常 | 提交“发现异常” | 事件进入核验异常；可重新核验或终止 |
| AC-18 | 终止事件 | 事件执行中 | 终止并确认 | 全部停止；事件为已终止；记录生成；不标记完成 |
| AC-19 | 记录 | 完成/终止事件 | 进入记录页锥桶页签 | 列表展示状态、L/d/N、主桶、创建时间；点击可查看详情；有跳过显示带异常完成 |
| AC-20 | 轮询生命周期 | 执行页可见 | 切后台/返回再进入 | 后台停止轮询；返回后继续 1Hz 刷新；最后更新时间更新 |
| AC-21 | 离线/断网 | 设备离线或手机断网 | 观察执行页 | 设备显示“离线”；手机断网显示网络错误；两者不混淆；不伪造实时状态 |
| AC-22 | 进行中事件互斥 | 已有非终态事件 | 尝试新建 | 发布入口禁用/服务端拒绝并返回现有事件 ID；可跳转执行页 |
| AC-23 | READY 超时 | 事件创建后未启动 | 等待 30 分钟 | 服务端自动取消 READY 事件，释放预留，允许新建 |

## 11. 风险与开放问题

### 11.1 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 设备行程/里程计精度不足 | 目标位置偏差，现场间距不符合预期 | 现场核验兜底；设备标定；未来引入定位 |
| 地图位置为估算 | 用户可能误以为是真实 GPS 位置 | 地图明确标注“估算，非 GPS”；不作为安全验收依据 |
| 手机与服务器断网 | APP 无法控制/查看，服务端可能继续编排 | 显示网络错误；提示使用设备急停；恢复后以服务端状态为准 |
| 旧服务端不支持转弯 | 新 APP 添加转弯后服务端按直行执行 | 创建后强制校验回显；不一致自动取消 |
| 人工跳过被滥用 | 绕过链路，增加现场风险 | 仅异常阻断、仅从桶、三项确认、原因/处置留痕、结果为带异常完成 |
| 设备离线/停止未确认 | 现场不知道设备是否停止 | 显式“离线/停止未确认/需现场处置”；禁止静默释放 |
| 同一作业人员多事件 | 设备占用冲突、状态混乱 | 服务端限制单个非终态事件；READY TTL |
| 设备绑定码缺失 | 无法创建事件 | 设备连接页校验；提示重新绑定 |
| 视频/地图依赖网络 | 辅助能力不可用 | 故障不影响状态展示和控制 |

### 11.2 开放问题

| 编号 | 问题 | 现状/建议 |
|---|---|---|
| Q-1 | 事件名/备注输入框当前允许 40/120 字，但校验上限为 30/100 字 | 建议统一为 30/100，避免“能输入但提交失败” |
| Q-2 | N=0 时接口仍要求 d>0，APP 使用 1.0 占位 | 建议服务端允许 N=0 时省略 d，或明确文档口径 |
| Q-3 | 服务端未返回电量/套装时，APP 当前会补默认电量与默认套装 | 建议正式环境缺失时显示“未知/无套装”，避免演示数据误导 |
| Q-4 | 执行页目前只显示“最后更新时间”，未显式标注“非实时” | 建议超过阈值显示“非实时”，与需求规格一致 |
| Q-5 | 记录页当前无筛选、无本地缓存 | 列入 P1 |
| Q-6 | 核验备注上限 UI 为 120 字，接口/其他备注上限 100 字 | 建议统一 |
| Q-7 | 手动干预左转/右转的具体角度由设备/服务端定义 | 需在设备协议中明确，APP 只发方向 |
| Q-8 | 设备停车容差、到达判定阈值 | 需硬件/固件给出可配置值 |
| Q-9 | 多转弯下 `causeReportId`、步骤日志的展示粒度 | 当前 APP 只展示 nextExpected；详情日志可在记录页后续扩展 |
| Q-10 | 人工跳过后的设备恢复/再次移动处理 | 需服务端明确异常标记与审计规则 |

### B.1 标准直行

| 设备 | 目标行程 |

| 从 2 | 10 m |
| 从 3 | 0 m（无需移动，仍需核验） |

| 设备 | 目标行程 | 说明 |
|---|---|---|

`L=25 m, d=10 m, N=3`

```text
N×d = 30 m > L = 25 m

```

### B.5 路线转弯示例

`L=60 m, d=10 m, N=2, 转弯点 atM=45 m，左转 90°`

|---|---|---|
