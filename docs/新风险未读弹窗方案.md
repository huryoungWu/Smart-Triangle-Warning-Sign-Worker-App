# 新风险未读弹窗方案（未实现）

> 目标：当出现一条**用户还没读过**的新风险（前方事故/施工/散落物…）时，在 App 任意页面主动弹出提示；
> 已读状态保存在**手机本地**，同一条不再重复打扰。
>
> 状态：**方案（尚未实现）**　日期：2026-10-16　涉及：App（Kotlin/Compose）+ Mock 服务端（server.js）

## 一、背景与目标

- 现状：风险地图只有**打开页面才拉数据**（`feature/risk/RiskScreen.kt` 的 `LaunchedEffect(center)` 一次性拉取），
  每次进页面都是全新列表 —— 没有"新风险提醒"，用户在现场作业时不会被主动提示。
- 目标：新风险出现且用户未读 → 弹窗提醒；读过的同一条 → 不再弹。
- 非目标（本次不做）：系统通知 / 后台常驻提醒（需前台服务或 FCM）、服务端推送（WS/SSE 仍预留，继续走轮询）、
  风险列表里的"未读红点"标记。

## 二、已确认口径

| 项 | 结论 |
|---|---|
| 演示数据来源 | Mock 服务端「实时风险」轮换（默认每 120 秒换一条新 id；环境变量可调、可关） |
| 检查时机 | App **前台每 60 秒**查一次 + 回到前台立即查一次（无前台服务，后台不查也不弹） |
| 弹窗范围 | **所有页面都弹**（含任务执行页） |
| 已读判定 | **关闭弹窗即已读**（点「查看详情」或「知道了」都算） |

## 三、数据流

```
手机定位(中心点) → 每 60s GET /api/v1/risks?radiusKm=2（复用 RiskRepository）
      → 过滤：今天 + 有车道 + ≤2km（与风险列表同一口径）
      → 与本地已读 id 集合比对 → 取最近的一条弹窗（同批其余：文案提示「另有 N 条」）
      → 关闭即写本地已读 → 弹下一条（若有）
```

## 四、改动清单

### 1. 本地已读表 —— 新增 `core/data/risk/RiskReadStore.kt`

- Preferences DataStore，新文件名 `risk_read`；沿用工程既有做法（**DataStore + JSON 字符串**，不引入 Room）——
  参考 `core/data/record/WorkRecordRepository.kt`
- 存 `{"<riskId>": <已读时间戳>}`；**上限 500 条 + 超过 7 天自动清**
  （实时风险每 2 分钟一个新 id，必须有上限/过期，否则无限增长）
- 接口：`val readIds: Flow<Set<String>>`、`suspend fun markRead(ids: Collection<String>)`、
  `val baselined: Flow<Boolean>` + `suspend fun markBaselined()`
- 在 `di/ServiceLocator.kt` 注册（与 `settingsRepository` 同级）

### 2. 纯逻辑 + 单测 —— 新增 `core/model/risk/RiskAlertRules.kt`

- `fun pickNewRisks(fetched: List<Accident>, readIds: Set<String>, now: Long): List<Accident>`
  - 复用既有口径：`lane != null`、`TimeFormat.isToday(...)`、`distanceM <= RiskRadius`；排除已读 id；按距离从近到远
- 常量：`POLL_INTERVAL_MS = 60_000`、`MIN_POPUP_GAP_MS = 30_000`（防连续弹）
- 单测 `app/src/test/java/com/example/myapplication/RiskAlertRulesTest.kt`：
  新 id 才返回 / 已读不再返回 / 非今天·无车道·超 2km 不返回 / 按距离排序

### 3. 轮询 ViewModel —— 新增 `feature/risk/RiskAlertViewModel.kt`（Activity 级）

- 依赖：`RiskRepository`、`RiskReadStore`、`SettingsRepository`（隐私同意门）、
  中心点提供者（`mapVm.phoneFix`；无定位时用与风险页相同的演示基准点 `39.9928, 116.4004`）
- `start()`/`stop()` 幂等；start 立即查一次，之后每 60s 一次
- **首次运行静默基线**：本地无任何已读记录时，把当前拉到的 id 全部标记已读、不弹窗（避免刚装上就弹一堆）
- 一次只弹一条（最近的），`extraCount` 记录同批其余条数；两条弹窗至少间隔 30s
- `onAlertClosed()` → 整批标记已读 + 弹下一条
- 拉取失败（`HttpRiskRepository` 已把异常降级为空列表）→ 静默跳过，不弹、不写已读
- 作业人员自己上传的快照登记（`source=worker`）**同样当新风险弹**

### 4. 弹窗 UI —— 新增 `core/ui/NewRiskAlertDialog.kt`

- Material3 `AlertDialog`，红色警示（`WarningRed/WarningRedBg`，与 `AppDialog.Warn` 同色系）
- 内容：标题 / `类型 · 第 N 车道 · 距您 xx` / 发生时间 / 描述（≤2 行）；有图时左侧缩略图（复用 `core/ui/RemoteImage.kt`）
- 按钮：主「查看详情」、次「知道了」（都关闭并算已读）
- **只由 `AppNavHost` 渲染一次**，遵守 `core/ui/AppDialogRenderer.kt` 顶部
  "全应用禁止页面私自拼 AlertDialog"的统一出口约定；与既有 `state.dialog` **互斥**
  （`state.dialog != null` 时本轮延后，避免两个弹窗叠加）

### 7. Mock 服务端「实时风险」轮换 —— `tools/mock-server/server.js`

- 新增 `LIVE_RISK_INTERVAL_MS`（默认 `120000`，设 `0` 关闭）：

  ```js
  const round = Math.floor(now / LIVE_RISK_INTERVAL_MS);
  risks.push({ id: `r-live-${round}`, ...LIVE_POOL[round % LIVE_POOL.length],
               occurredAt: now - (now % LIVE_RISK_INTERVAL_MS), lane: /*1~8*/ });
  ```

- `LIVE_POOL` 4~6 条候选（方向/距离/类型/车道/文案各异，均 ≤2km、**都带车道**）；
  上一轮的 id 自动从列表消失 → 每 2 分钟"冒出一条新风险"，正好触发弹窗
- 默认开启（演示即用）；需要安静时 `LIVE_RISK_INTERVAL_MS=0 node server.js`

## 五、边界与风险

| 边界 | 说明 |
|---|---|
| 后台不弹 | 无前台服务，App 不在前台就不轮询；如需后台提醒要另做（前台服务/FCM），本次不做 |
| 首次安装不刷屏 | 首次运行静默基线，只提醒"基线之后出现的新风险" |
| id 必须稳定 | 服务端（含 Mock）对同一条风险必须始终给同一个 id，否则客户端每轮都当新风险 |
| 拉不到数据 | `HttpRiskRepository` 已把异常降级为空列表 → 不弹、不写已读，静默重试 |
| 弹窗打架 | 与 `VehicleViewModel` 的安全弹窗（失联/急停）互斥：安全弹窗优先，风险弹窗等它关掉 |
| 作业中打扰 | 已确认所有页面都弹；弹窗不阻塞操作，可立即关掉（若想改成"作业页只出横幅"，只需在 AppNavHost 判断当前路由） |

## 六、验证方式（落地后执行）

1. **单测**：`./gradlew :app:testDebugUnitTest`（新增 `RiskAlertRulesTest`，原 `RiskListFiltersTest` 等全绿）
2. **Mock**：`LIVE_RISK_INTERVAL_MS=5000 node server.js` → 隔 6 秒 curl 两次 `/api/v1/risks`，
   确认 `r-live-<round>` 的 id 会变、带 lane、≤2km
3. **真机**：`./gradlew :app:installDebug` + `adb reverse tcp:8080 tcp:8080` →
   跳过登录进 App → 等 ≤2 分钟出现「前方新风险」弹窗 → 点「查看详情」进详情页 →
   返回后确认同一条不再弹、下一轮才弹
4. **回归**：风险页仍是"今天 6 条演示 + 实时 1 条 + 已上传的"；杀掉 Mock 服务端后轮询静默（不弹窗、不写已读）
