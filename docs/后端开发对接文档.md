## 1. 总体要求

### 1.1 架构定位

```
APP（Android） ──HTTP──►  正式服务端（本文档） ──TCP/私有协议──►  车端 ESP32（三角警示牌小车）
                              │
                              └──拉流/转发──► 车端摄像头（每台设备一路视频）
```

- 服务端是**设备网关 + 业务后端**：下发控制命令到车端、汇总车端状态、存业务数据、**中继视频流**。
- APP 与车端**不直连**（生产形态）；所有设备访问经服务端。

### 1.2 硬性要求

| 项 | 要求 |
|---|---|
| 协议 | HTTP/1.1+，`Content-Type: application/json; charset=utf-8`（视频除外） |
| 鉴权 | `Authorization: Bearer <token>`；视频流允许 `?token=` 查询参数（播放器不能自定义 Header） |
| 时间 | 毫秒时间戳（`Date.now()` 口径，13 位） |
| 坐标 | **车端 GPS 上报 WGS-84**；风险数据（`risks`）坐标为 **GCJ-02**（高德）；两者不可混用 |
| 并发 | 设备状态 1Hz 轮询 ×N 用户；视频流每观看端 1 路长连接（10fps，约 1~2 Mbps/路） |
| 幂等 | 作业记录上传必须支持 `Idempotency-Key`（详见 §7） |
| HTTPS | 生产必须 HTTPS；联调阶段 HTTP 可接受 |

### 1.3 联调基座

APP 侧 `SERVER_BASE_URL` 指向服务端根路径（联调为 `http://127.0.0.1:8080`）。
**先按本文实现接口 → 用 `tools/mock-server/server.js` 对照字段 → 再替换为正式后端**，APP 不改代码（换 Base URL 即可）。

## 2. 通用约定

### 2.1 成功响应

两种形态（**不使用** `{code,data}` 大信封）：

```jsonc
// ① 资源本体（查询类）
{ "deviceId": "TC-001", "mode": "standby", ... }

// ② 列表（分页三件套固定：items/page/size/total）
{ "items": [ ... ], "page": 1, "size": 20, "total": 12 }
```

### 2.2 错误响应（统一信封）

```jsonc
{ "error": { "code": "bad_request", "message": "设备编号不能为空且不超过 32 字符", "detail": "可选" } }
```

| HTTP | code | 含义 |
|---|---|---|
| 400 | `bad_request` | 参数缺失/非法 |
| 401 | `bad_credentials` / `unauthorized` | 账号密码错误 / token 失效（APP 会跳登录） |
| 404 | `not_found` / `unknown_device` | 资源/设备不存在 |
| 409 | `already_bound` | 设备已被其他账号绑定 |
| 400 | `cannot_unbind_builtin` | 内置设备不可解绑（若保留该规则） |
| 5xx | `internal` | 服务端内部错误 |

### 2.3 空值约定

响应字段**可整体省略**（APP 解析口径：缺字段回落安全默认，不必给 `null` 也可）；
给了 `null` 也可以，二者等价。枚举值 APP 兼容**小写 token**（如 `"mode": "standby"`），勿用中文或大写。

## 3. 认证（登录/登出）

### 3.1 登录 `POST /api/v1/auth/login`

```jsonc
// 请求
{ "username": "demo", "password": "123456" }

// 200 响应
{
  "token": "eyJ...",
  "refreshToken": "eyJ...",
  "expiresIn": 7200,                       // 秒
  "user": { "id": "u-1001", "name": "张三", "role": "operator", "phone": "138****0000" }
}
```

- 账号密码错误 → `401 {"error":{"code":"bad_credentials", ...}}`（APP 登录页显示「用户名或密码错误」）。
- ⚠️ Mock「任意账号自动建号」**禁止照搬**：正式后端必须真实校验。

### 3.2 刷新 `POST /api/v1/auth/refresh`

请求 `{ "refreshToken": "..." }` → 200 `{ "token", "refreshToken", "expiresIn" }`。

### 3.3 当前用户 `GET /api/v1/auth/profile`（Bearer）

→ 200 `{ "id", "name", "role", "phone" }`（与登录响应 `user` 同构）。

### 3.4 登出 `POST /api/v1/auth/logout`（Bearer）

→ **204 无 body**；服务端作废 token（refreshToken 一并作废）。

## 4. 设备台账与绑定

### 4.1 设备列表 `GET /api/v1/devices`（Bearer）

**按登录用户过滤**（用户只看到自己绑定的设备）：

```jsonc
{
  "devices": [
    {
      "deviceId": "TC-001",
      "name": "三角警示牌一号车",
      "bound": true,
      "online": true,
      "started": true,            // 是否已开机（连接页「是否开始」）
      "available": true,          // 是否可用（连接页「是否可用」）
      "batteryPercent": 86,       // 可空（无电量来源时省略）
      "fw": "0.3.1",
      "lastSeenAt": 1760083200000
    }
  ]
}
```

### 4.2 绑定 `POST /api/v1/devices/bind`（Bearer）

```jsonc
// 请求
{ "deviceId": "TC-001" }
// 201
{ "device": { "deviceId": "TC-001", "name": "三角警示牌一号车", "bound": true } }
```

- `deviceId` 必填，≤32 字符，否则 400 `bad_request`。
- 已被其他账号绑定 → 409 `already_bound`。
- ⚠️ Mock「未知编号自动注册」**禁止照搬**：正式后端必须校验设备真实存在（车端入库/出厂台账），否则 404 `unknown_device`。

### 4.3 解绑 `DELETE /api/v1/devices/{deviceId}/bind`（Bearer）

→ 204 无 body。不存在/不属于当前账号 → 404 `not_found`。

### 4.4 设备详情 `GET /api/v1/devices/{deviceId}`（Bearer）

```jsonc
{
  "deviceId": "TC-001", "name": "三角警示牌一号车", "fw": "0.3.1",
  "sn": "ESP32-8F2A11", "boundAt": 1760000000000,
  "lastSeenAt": 1760083200000, "online": true,
  "capabilities": { "gps": true, "camera": true, "battery": true, "tilt": false, "obstacle": false }
}
```

> `capabilities.camera=false` 时 APP 将视频卡片整卡置灰（§9）。

## 5. 设备实时状态（1Hz 轮询）

### 5.1 `GET /api/v1/device/status?deviceId=TC-001[&lat=&lng=]`（Bearer）

- APP **每 1 秒**轮询当前选中设备（多车时只轮询选中那台）。
- 可选参数 `lat/lng`（GCJ-02）：APP 定位可用时上报手机位置，**仅作审计/锚点用途**；正式后端可忽略。

### 5.2 响应（APP `DeviceJson` 解析口径，字段名不可改）

```jsonc
{
  "deviceId": "TC-001",
  "fw": "0.3.1",
  "online": true,
  "mode": "standby",            // standby | manual | auto | safe_stop
  "motion": "idle",             // idle | moving | fault
  "estopLocked": false,
  "stopSource": "none",         // none | manual | estop | link_loss | ...
  "light": "off",               // off | on | blink
  "task": {
    "id": "t-abc",              // 无任务时整个 task 可为空对象或省略字段
    "kind": "fixed_distance",
    "source": "app",
    "targetM": 20,
    "traveledM": 8,
    "state": "running",         // idle | running | done | failed | canceled
    "stage": "auto_driving",    // 可省略
    "resultNote": null,         // 可省略
    "heading": 25,
    "segments": [
      { "action": "fwd", "value": 20, "state": "running", "progress": 0.4 }
      // action: fwd | turn；state: pending | waiting_confirm | running | done | failed | skipped
    ]
  },
  "odo": { "leftPulse": 4000, "rightPulse": 4000, "traveledM": 8, "speedMps": 0.25, "diffPulse": 0 },
  "batteryPercent": 86,          // 可省略
  "tilt": null,
  "obstacle": null,
  "ts": 1760083200000,

  "gps": {                       // 可选：无 GPS 模块时整体省略（APP 自动走「行程估算」降级）
    "lat": 39.9928123,           // WGS-84（APP 端自行转 GCJ-02 上高德）
    "lng": 116.4004123,
    "acc": 5.0,
    "speed": 0.25,
    "heading": 25,
    "state": "fixed",            // fix | float | ...
    "at": 1760083200000
  }
}
```

**关键约定**：
- `gps` 坐标为 **WGS-84**（真实车端 GPS 原始值即可，APP 做偏移转换）；
- APP 用 `ts` 判「非实时」：超过阈值显示离线提示；
- 任务段 `segments` 顺序即执行顺序，`progress` 为 0..1。
- ⚠️ Mock 用「轮询节奏推进状态机」仅为模拟车端；正式后端应**转发车端 1Hz 上报的实况**。

## 6. 控制命令

### 6.1 通用接口 `POST /api/v1/device/command`（Bearer）

```jsonc
// 请求：type + 参数（见全表）
{ "deviceId": "TC-001", "type": "move", "dir": "fwd" }

// 200 接受
{ "accepted": true, "cmdId": "c-1a2b" }

// 200 拒绝（注意 HTTP 仍是 200，业务拒绝在 body 里）
{ "accepted": false, "reason": "task_running" }
```

### 6.2 命令类型全表

| type | 参数 | 语义 |
|---|---|---|
| `move` | `dir`: `fwd` \| `back` \| `left` \| `right` | 手动点动（按住走松手停） |
| `stop` | — | 停车（任务执行中视为「手动停止」并熔断任务） |
| `estop` | — | 急停上锁（`mode=safe_stop`，任务熔断） |
| `resume` | — | 急停解锁（仅 `estopLocked` 时接受） |
| `light` | `mode`: `off` \| `on` \| `blink` | 灯光（与运动分离，可随时调） |
| `odo_reset` | — | 里程清零（行驶/任务中拒绝） |
| `task_start` | 见 §6.3 | 启动布置任务 |
| `segment_confirm` | — | 确认执行下一段（分段确认模式） |
| `task_cancel` | — | 取消当前任务 |
| `recover` | — | 回收（按已行驶里程原路返回） |

### 6.3 `task_start` 载荷（两种形态）

```jsonc
// 形态 1：单段快捷（定距布置）
{ "deviceId": "TC-001", "type": "task_start", "targetM": 20, "kind": "fixed_distance", "light": "blink" }

// 形态 2：多段路线（发布任务表单）
{
  "deviceId": "TC-001", "type": "task_start", "kind": "fixed_distance",
  "mode": "auto",               // auto | segment_confirm（分段人工确认）
  "light": "blink",
  "segments": [
    { "action": "fwd", "value": 20 },    // value = 米
    { "action": "turn", "value": 90 }    // value = 度（+左/-右，|5|~180）
  ]
}
```

**参数校验（与 APP/车端一致，拒绝时 reason 如下）**：

| 限制 | 值 | 违反时 reason |
|---|---|---|
| 段数 | ≤ 10 | `too_many_segments` |
| 单段距离 | 1 ~ 50 米 | `segment_out_of_range` |
| 转向角度 | 绝对值 5 ~ 180 度 | `segment_out_of_range` |
| 总距离 | ≤ 200 米 | `param_out_of_range` |
| `targetM`（形态1） | 1 ~ 50 米 | `param_out_of_range` |

### 6.4 reason 码全表

`estop_locked`（急停锁定）、`task_running`（任务执行中）、`param_out_of_range`、`segment_out_of_range`、`too_many_segments`、`not_locked`（未锁定时 resume）、`busy`（行驶/任务中不可清里程）、`no_task`、`not_waiting_confirm`、`already_home`（已在家/零里程）、`link_loss`（与车端失联）。

### 6.5 遥控看门狗（车端/网关需实现）

手动 `move` 后 **800ms** 无新指令 → 自动停车（防手机断网失控）。APP 不发显式 stop 时依赖此机制。

## 7. 作业记录上传与查询

### 7.1 上传 `POST /api/v1/tasks`（Bearer）

- 触发时机：任务核验通过后 APP 自动上传（字段即 `WorkRecord`）。
- **必须支持幂等**：Header `Idempotency-Key: <本地记录id>`；重复提交返回同一条记录（201，不新建）。

```jsonc
// 请求（APP TaskUploadJson 精确字段）
{
  "id": "9f2a13cd",                    // 本地记录 id（= Idempotency-Key）
  "name": "自动布置",
  "kind": "fixed_distance",
  "mode": "auto",                      // 可空
  "startedAt": 1760083200000,
  "finishedAt": 1760083320000,
  "segments": [ { "action": "fwd", "value": 20 }, { "action": "turn", "value": 90 } ],
  "targetM": 20,
  "traveledM": 20,
  "deviceResult": "done",              // done | failed | canceled
  "deviceResultNote": null,
  "verifyResult": "pass",              // pass | fail | pending
  "verifyNote": null,
  "abnormalNote": null
}

// 201 响应
{ "id": "srv-7d10", "receivedAt": 1760083400000 }
```

APP 会把返回的 `id` 存为「服务端单号」展示在记录页。

### 7.2 列表 `GET /api/v1/tasks?deviceId=&from=&to=&page=1&size=20`（Bearer）

→ `{ "items": [ <记录对象>... ], "page", "size", "total" }`（记录对象与上传载荷同构 + `receivedAt` + `clientId`）。

### 7.3 详情 `GET /api/v1/tasks/{id}`（Bearer）

→ 记录对象 + `eventNo`（事件编号，格式建议 `EV-YYYYMMDD-XXXX`，APP 原样展示）。

## 8. 快照上传

### 8.1 `POST /api/v1/snapshots`（Bearer，`multipart/form-data`）

- 触发时机：任务开始自动抓拍、任务结束自动抓拍、执行中手动「捕捉快照」。
- **当前 APP 仅上报元数据**（image 部分暂省略）；接真机后可能补 `image` 文件部分，**两种都要兼容**（字段缺失/存在都正常工作）。

| 表单字段 | 类型 | 说明 |
|---|---|---|
| `id` | text | 本地快照 id |
| `deviceId` | text | **所属设备（用于从该设备流截帧）** |
| `taskName` | text | 任务名（可空） |
| `eventLabel` | text | 事件标签：如「任务开始（自动抓拍）」「任务结束（自动抓拍）」「现场抓拍」 |
| `capturedAt` | text | 抓拍时间（毫秒时间戳） |
| `note` | text | 备注（可空） |
| `lat` / `lng` | text | 可选：抓拍点坐标 |
| `image` | file | 可选：快照图片（当前不传） |

```jsonc
// 201 响应
{ "id": "snap-0007", "url": "https://<server>/media/snap-0007.jpg", "placeholder": true, "riskId": "r-snap-0007" }
```

### 8.2 服务端必须做的两件事（生产语义）

1. **存图**：优先用客户端 `image`；未传时**从该 `deviceId` 的视频流截取当前帧**（见 §9.3），落盘并经 `url` 可回放；
2. **登记风险**：将快照登记为「作业人员上报」风险事件（`source: "worker"`），使其出现在 `GET /risks` 中——
   即 APP 的**「上传后才能在风险中展示」**约定。`riskId` 一并返回。

### 8.3 列表 `GET /api/v1/snapshots?deviceId=&from=&to=&page=1&size=20`（Bearer）

→ `{ "items": [ { "id", "deviceId", "taskName", "eventLabel", "capturedAt", "note", "hasImage" }... ], "page", "size", "total" }`

## 9. 视频流（重点：必须接真实摄像头）

> **本节是正式后端与 Mock 最大的差异点。**
> Mock（`makeFrame`）用像素算法**画**出演示动画帧顶替视频——这是为了无硬件联调，**不是产品形态**。
> 正式后端必须提供**真实车端摄像头**画面：APP 上的「实时视频」「事故视频」「快照截帧」都来自真实拍摄。

### 9.1 总体要求

| 项 | 要求 |
|---|---|
| 视频源 | 每台设备的**车端摄像头**（如 ESP32-CAM）；**按 `deviceId` 各自一路**，画面必须是该设备的实拍 |
| 禁止 | 演示动画、测试图卡、所有设备共用一路、同一画面糊弄多设备 |
| 区分度 | 不同设备的画面**必须不同**（本就是不同摄像头实拍） |
| 鉴权 | 支持 `?token=<accessToken>`（短时效流 token 建议 5 分钟）；失效返 401 |
| 延迟 | 实时视频端到端 **≤ 3 秒**（MJPEG 方案预期 1~3s） |
| 分辨率 | 默认 640×480@10fps（支持 `w`/`fps` 参数降采样/降帧） |
| 单设备 | 同一台设备可多个观看端并发拉同一路流（服务端负责扇出） |

### 9.2 实时视频 `GET /api/v1/device/video/stream?deviceId=TC-001[&token=][&w=640][&fps=10]`

```
→ 200 Content-Type: multipart/x-mixed-replace; boundary=frame
   （持续输出 JPEG 帧：每帧 --frame\r\nContent-Type: image/jpeg\r\nContent-Length: N\r\n\r\n<bytes>\r\n）
```

- **实现要求**：服务端从该设备摄像头拉流（如 `GET http://<车IP>/stream` MJPEG）**原样中继**给 APP；
  也可服务端收 RTSP/其他后转封装（HLS/HTTP-FLV），但**首期以 MJPEG 中继为准**（APP `MjpegStreamView` 已实现该解码）。
- `deviceId` **必传语义**：指定取哪台设备的流；设备不存在/无摄像头 → 404/400（勿返回 200 空流）。
- 车端断流：服务端应结束响应或转发错误帧，APP 会自动重连（1s 退避）；**勿无限占着连接发黑帧**。
- 帧格式：JPEG（ESP32-CAM 原生输出）；APP 端 `BitmapFactory` 自动识别 PNG/JPEG，出 PNG 亦可。

### 9.3 单帧抓拍 `GET /api/v1/device/video/snapshot.jpg?deviceId=TC-001[&token=]`

```
→ 200 Content-Type: image/jpeg
```

- 返回该设备视频流的**当前帧**（与 §8 快照截帧同源）。
- 用途：低带宽场景取帧；快照无 `image` 时服务端截帧的数据源。

### 9.4 事故视频（风险详情）

事故详情页直接播放 `GET /risks` 返回的 `videoUrl`（可直连的 HTTP 地址）：

- `videoUrl` **必须指向事发设备那一路**（带该事件对应设备的 `deviceId`），例如
  `https://<server>/api/v1/device/video/stream?deviceId=TC-002`，或该事件录制的 MP4/HLS 回放地址；
- 无视频则 `videoUrl: null` + `hasVideo: false`（APP 显示「暂无」占位）；
- ⚠️ Mock 演示数据里的事故视频也是合成流——生产应为**真实事故录像/事发设备实拍**。

### 9.5 备选传输（可选，不影响首期）

| 方案 | 端点形态 | 说明 |
|---|---|---|
| HLS | `GET /api/v1/device/video/live.m3u8?deviceId=&token=` | 服务端 ffmpeg 转封装；APP `VideoStreamView` 已接 ExoPlayer（media3）自动识别 `.m3u8/.flv/.mp4` |
| HTTP-FLV | `.flv` 长连接 | 低延迟备选 |

> APP 侧 `VideoStreamView` 按 URL 后缀智能分发：`.m3u8/.flv/.mp4` → ExoPlayer；其他 → MJPEG 解析。
> 首期继续用 MJPEG 即可（无需 APP 发版）。

### 9.6 能力协商

设备无摄像头时 `GET /devices/{id}` 的 `capabilities.camera=false`，APP 将视频卡片置灰并显示「设备无摄像头」。

## 10. 道路风险数据

### 10.1 `GET /api/v1/risks?lat=39.9928&lng=116.4004&radiusKm=2`（Bearer）

围绕查询点返回周边风险 + 作业人员上传登记的风险（§8.2）：

```jsonc
{
  "risks": [
    {
      "id": "r-1001",
      "title": "两车追尾，占用左侧两车道",
      "type": "rear_end",       // breakdown | rear_end | construction | rollover | debris | other
      "lat": 39.9935,           // GCJ-02（高德）
      "lng": 116.4012,
      "occurredAt": 1760080000000,
      "description": "高峰时段两辆小客车发生追尾……",
      "hasPhoto": true,
      "hasVideo": true,
      "photoUrls": [ "https://<server>/media/acc-1001-1.jpg" ],
      "videoUrl": "https://<server>/api/v1/device/video/stream?deviceId=TC-002",  // 事发设备那一路；无视频则 null
      "source": "worker"        // worker=作业人员上传 / external=外部数据源（可省略默认 external）

  ]
```

- 事故详情页：`photoUrls` 首图 + `videoUrl` 直接播放（见 §9.4）。

## 12. Mock 禁止照搬清单

`tools/mock-server/server.js` 仅为**联调参考实现**，以下行为**正式后端一律不得保留**：

| # | Mock 行为 | 正式要求 |
|---|---|---|
| 1 | **`makeFrame` 合成视频动画帧** | 视频必须来自**真实车端摄像头**（§9） |
| 2 | 所有事故视频/快照截帧也用合成帧 | 事故视频=事发设备实拍/录像；快照=该设备流截帧或车端抓帧 |
| 3 | 登录「任意账号自动建号」、鉴权宽松（无 token 按 demo） | 真实账号体系；无/失效 token → 401 |
| 4 | 绑定「未知设备自动注册」 | 校验设备真实存在，否则 404 `unknown_device` |
| 5 | risks 内置 6 条演示事故 + 坐标「就近放置」 | 真实风险数据源；无坐标事件按生产语义过滤 |
| 6 | 状态机由 `/status` 轮询节奏推进（假车） | 转发真实车端 1Hz 上报 |
| 7 | 内存 + `data/state.json` 持久化 | 数据库 |
| 8 | `EMIT_GPS` 位置=手机锚点投影 | 真实车端 GPS（WGS-84） |
| 9 | 响应 `Access-Control-Allow-Origin: *` | 按需收紧 |

## 13. 联调验收清单

按顺序验收（每项 APP 侧已有现成界面可验）：

| # | 验收项 | 通过标准 |
|---|---|---|
| 1 | 登录 | demo/正确密码进设备页；错误密码提示；token 失效跳登录 |
| 2 | 设备列表 | 只显示当前账号设备；`started/available/电量` 与车端一致 |
| 3 | 绑定/解绑 | 扫码绑定成功；他账号已绑 → 409；解绑后列表消失 |
| 4 | 状态轮询 | 连接页/执行页状态 1Hz 刷新；断网显示「非实时」 |
| 5 | 手动遥控 | 前进/后退/左右点动；松手 800ms 内停车；急停/解锁生效 |
| 6 | 任务发布执行 | 多段路线执行、段进度、完成/取消/熔断；`task_start` 参数越界被拒 |
| 7 | **实时视频** | **执行页播放该设备真实画面；换设备连接画面随之切换；断流自动重连** |
| 8 | 快照 | 任务开始/结束自动抓拍、手动补拍；风险页出现「作业人员上报」；照片可回放 |
| 9 | 事故视频 | 风险页不同事故视频画面**互不相同**（各自事发设备） |
| 10 | 作业记录 | 核验通过自动上传；服务端单号显示；重复上传幂等不重复 |
| 11 | 坐标 | 地图车辆位置正确（WGS-84→GCJ-02 后落点准确） |
